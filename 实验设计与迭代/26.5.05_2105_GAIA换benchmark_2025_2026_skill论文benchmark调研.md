## 一页结论

如果目标是“跟最近热门 Agent Skills / skill learning 工作对齐”，第一批不建议从 `SQLBench / AgentBench DB` 开主实验。它们很干净，适合 smoke 和机制调试；但近两年显式 skill 论文的主战场已经明显转向 `SkillsBench / SkillFlow / SkillLearnBench` 这类直接把 skill 当作评测对象的 benchmark，以及 `ALFWorld / WebShop / ScienceWorld / WebArena / BrowseComp / SealQA / OfficeQA` 这类被 skill 方法反复拿来展示迁移和自进化收益的环境。

优先级排序：

1. **首选：SkillsBench**
   2026 年新 benchmark，直接评估 `SKILL.md + 资源 + verifier` 是否提升 agent performance。它和我们当前的 skill 工件形态最接近，且官方用 `Codex CLI + GPT-5.2`、`Claude Code`、`Gemini CLI` 做过完整对照。适合做“我们这套 skill/critic/actor 框架是否真的能写出有效 skill”的主线。
2. **并行盯：SkillFlow**
   2026 年 4 月新 benchmark，166 个任务、20 个 workflow family，核心问题就是 lifelong skill discovery / patch / transfer。它和当前 BOOT/B1/B2 actor-critic 的关系最直接，适合展示“从轨迹到 skill patch，再迁到同 family 后续任务”的框架优势。
3. **小而新：SkillLearnBench**
   2026 年 4 月新 benchmark，20 个 skill-dependent 任务、15 个子域，按 skill quality、execution trajectory、task outcome 三层评分。规模小，适合快速做方法原型；代码刚开源，先做可运行性核对。
4. **经典对齐组：WebShop + ALFWorld + ScienceWorld**
   benchmark 年份较早，但 `SkillNet`、`SkillRL`、`ExpeL`、ICRL/self-generated examples 等工作仍在使用。若需要和“经验学习 / skill library”论文横比，至少应覆盖 `WebShop` 或 `ALFWorld`。
5. **搜索/浏览/文档 QA 组：WebArena / BrowseComp / SealQA / OfficeQA**
   `SkillWeaver` 用 WebArena，`EvoSkill` 用 OfficeQA、SealQA 并迁移到 BrowseComp。它们比 GAIA 更聚焦，但 BrowseComp/SealQA 仍有 web/search 波动。适合作为第二阶段“搜索技能 / 证据技能”迁移集。
6. **工程工作流组：Terminal-Bench / Harbor / SWE 类任务**
   SkillsBench 本身建立在 Harbor/container/verifier 思路上，Terminal-Bench 仍值得长期跟。当前本机 Docker/Harbor 权限是现实阻塞，暂时放在 SkillsBench 可运行性之后。
7. **本地干净 smoke：SQLBench / BIRD / Spider / AgentBench DB**
   继续保留。它们适合调 prompt、状态机、score plumbing 和成本估算；主论文对齐价值低于上面几组。

## 近两年 Skill 论文实际跑了什么

### 2026 年直接围绕 Agent Skills 的新 benchmark

- `SkillsBench: Benchmarking How Well Agent Skills Work Across Diverse Tasks`，arXiv 2026-02。
  - 论文定义 Agent Skills 为可移植的结构化程序性知识包，包含 `SKILL.md` 和可选 scripts/references。
  - 官方最终评估写明 `84` 个任务、`11` 个 domain、确定性 verifier、`7,308` 条 trajectory；摘要写 `86` 个任务。文内解释评估分母为 `84`。
  - 使用 `Claude Code`、`Gemini CLI`、`Codex CLI`，模型包括 `GPT-5.2`、`Claude Opus 4.5/4.6`、`Claude Sonnet 4.5`、`Claude Haiku 4.5`、`Gemini 3 Pro/Flash`。
  - 官方主结论：curated Skills 平均提升 `+16.2pp`；self-generated Skills 平均无收益，说明“临场让模型自己写 skill”当前很不稳。
  - 来源：[arXiv 2602.12670](https://arxiv.org/abs/2602.12670)、[GitHub benchflow-ai/skillsbench](https://github.com/benchflow-ai/skillsbench)。

- `SkillFlow: Benchmarking Lifelong Skill Discovery and Evolution for Autonomous Agents`，arXiv 2026-04。
  - 166 个 runnable Harbor tasks、20 个 workflow families、5 个 broad domains；每个 family 按共享 DAEF 组织。
  - 协议是 Agentic Lifelong Learning：空 skill library 起步，按 family 顺序做题，从 trajectory/rubric 写 skill patch，再把更新后的 library 带到后续任务。
  - 论文报告 `Claude Opus 4.6` 从 `62.65%` 到 `71.08%`，增益 `+8.43pp`；同时指出高 skill usage 不等于高 utility。
  - 来源：[arXiv 2604.17308](https://arxiv.org/abs/2604.17308)、[project page](https://zhangzi-a.github.io/SkillFlow-project-page/)、[HuggingFace dataset](https://huggingface.co/datasets/KouShi2/skillflow-bench)。

- `SkillLearnBench: Benchmarking Continual Learning Methods for Agent Skill Generation on Real-World Tasks`，arXiv 2026-04。
  - 20 个 verified skill-dependent tasks，15 个 sub-domains，来自真实 skill taxonomy。
  - 评分分三层：skill quality、execution trajectory、task outcome。
  - 论文用于比较 one-shot/self-feedback/teacher-feedback/skill creator 等 continual skill learning 方法。
  - 来源：[arXiv 2604.20087](https://arxiv.org/abs/2604.20087)、[GitHub cxcscmu/SkillLearnBench](https://github.com/cxcscmu/SkillLearnBench)。

### 2025-2026 方法论文反复使用的任务

- `SkillRL: Evolving Agents via Recursive Skill-Augmented Reinforcement Learning`，2026-02。
  - benchmark：`ALFWorld`、`WebShop`、7 个 search-augmented tasks。
  - 关键点：从 raw trajectories distill hierarchical `SkillBank`，skill library 与 policy 递归演化。
  - 来源：[arXiv 2602.08234](https://arxiv.org/abs/2602.08234)。

- `SkillNet: Create, Evaluate, and Connect AI Skills`，2026-02。
  - benchmark：`ALFWorld`、`WebShop`、`ScienceWorld`。
  - 关键点：大规模 skill ontology/repository，实验显示平均 reward 提升约 `40%`、execution steps 降约 `30%`。
  - 来源：[arXiv 2603.04448](https://arxiv.org/abs/2603.04448)。

- `EvoSkill: Automated Skill Discovery for Multi-Agent Systems`，2026-03。
  - benchmark：`OfficeQA`、`SealQA`，并把 SealQA skill 零样本迁移到 `BrowseComp`。
  - 关键点：失败分析 -> 新 skill/skill edit -> held-out validation promotion；`OfficeQA 60.6% -> 67.9%`，`SealQA 26.6% -> 38.7%`，`BrowseComp +5.3pp`。
  - 来源：[arXiv 2603.02766](https://arxiv.org/abs/2603.02766)。

- `SkillWeaver: Web Agents can Self-Improve by Discovering and Honing Skills`，2025-04。
  - benchmark：`WebArena` 和 real-world websites。
  - 关键点：web agent 自主发现网站交互 skill，把经验蒸馏成 reusable APIs；WebArena 相对成功率提升 `31.8%`。
  - 来源：[arXiv 2504.07079](https://arxiv.org/abs/2504.07079)。

- `Self-Generated In-Context Examples Improve LLM Agents for Sequential Decision-Making Tasks`，2025-05。
  - benchmark：`ALFWorld`、`Wordcraft`、`InterCode-SQL`。
  - 关键点：累积成功 trajectory 作为 in-context examples；`ALFWorld 73% -> 89%`，`Wordcraft 55% -> 64%`，`InterCode-SQL 75% -> 79%`。
  - 来源：[arXiv 2505.00234](https://arxiv.org/abs/2505.00234)。

- `XSkill: Continual Learning from Experience and Skills in Multimodal Agents`，2026-03。
  - benchmark：论文摘要称 5 个 multimodal benchmarks，公开摘要重点是 visual-grounded experience + skill 双流 continual learning。
  - 迁移判断：方向新，但当前我们主要是 text/tool executor，GUI/vision 适配成本高，作为后续观测对象即可。
  - 来源：[arXiv 2603.12056](https://arxiv.org/abs/2603.12056)。

- `CUA-Skill: Develop Skills for Computer Using Agent`，2026-01。
  - benchmark：`WindowsAgentArena`，best-of-three success `57.5%`。
  - 迁移判断：强相关于“技能图 + 参数化执行图”，但依赖 Windows GUI computer-use 环境，当前落地成本高。
  - 来源：[arXiv 2601.21123](https://arxiv.org/abs/2601.21123)、[project page](https://microsoft.github.io/cua_skill/)。

- `ExpeL`、`Voyager` 仍是方法脉络上的经典基线。
  - `ExpeL` 用 `HotpotQA / ALFWorld / WebShop / FEVER`，偏经验抽取与复用。
  - `Voyager` 用 Minecraft，强调 automatic curriculum + executable skill library。
  - 年份偏早，适合写 related work，当前主 benchmark 选择应让位给 2025-2026 新工作。
  - 来源：[ExpeL arXiv 2308.10144](https://arxiv.org/abs/2308.10144)、[Voyager project](https://voyager.minedojo.org/)。

## Benchmark Block 1：SkillsBench

### 基本定位

显式 Agent Skills benchmark。任务是 containerized professional workflows，agent 需要在文件系统、代码、数据、文档、脚本、测试之间工作。Skill 是一等输入工件：`environment/skills/<skill-name>/SKILL.md` 加可选 scripts/references。

### 哪些 skill 论文跑过

- `SkillsBench` 官方论文：主实验。
- 本地旧调研里提到的 `EvoSkills / CoEvoSkills`：以 SkillsBench 为主战场，报告 self-evolved skills 高于 curated skills。该条建议后续再单独核对最新 arXiv/代码，因为本轮主要用 SkillsBench 官方和仓库作为可信基准。

### 论文里的模型

- `Codex CLI + GPT-5.2`
- `Claude Code + Claude Opus 4.5 / 4.6 / Sonnet 4.5 / Haiku 4.5`
- `Gemini CLI + Gemini 3 Pro / Gemini 3 Flash`
- temperature `0`

### 普通 agent 做一题的自然工作流

1. 读取 `instruction.md` 和工作区文件。
2. 自动发现可用 skill，阅读 `SKILL.md` 和资源。
3. 根据任务目标修改文件、写脚本、运行命令、处理数据。
4. 根据测试失败信息修复。
5. verifier 运行 deterministic assertions，给 pass/fail。

### 规模与划分

- 官方摘要：`86` tasks、`11` domains。
- 评估正文：`84` evaluated tasks，`7` model-harness configurations，`3` skills conditions，总计 `7,308` valid trajectories。
- 无传统 train/dev/test；常用协议是同一任务在 `no skills / curated skills / self-generated skills` 条件下多次 trial。

### 评分方式

- deterministic verifier，binary pass/fail。
- 主指标：task-level pass rate。论文按每题 5 trials 平均，再对 `84` 题 fixed denominator 求均值。

### 迁移适配判断

适合点：

- 和当前 `SKILL.md` 工件最贴。
- verifier 干净，能减少 GAIA 的 web/search 偶然性。
- 任务够新，且官方直接覆盖 `Codex CLI + GPT-5.2`，可对齐“大家都在用的 skill 生态”。
- 能直接测试“手写/boot/actor 生成 skill 是否真的有用”。

主要阻塞：

- 依赖 container/Harbor/BenchFlow/uv 环境，需先做 smoke。
- 任务跨度大，第一轮要抽 10-20 个 core/extended 子集，避免成本爆。
- 官方 task 数不大，做 actor/critic train 时要防止把 eval 污染成训练集。

建议：

- 作为第一主线。先跑 `no skills` vs `provided skills` 的本地 sanity，再接我们自己的 `bootstrap/critic/actor` skill 生成。

## Benchmark Block 2：SkillFlow

### 基本定位

lifelong skill discovery / evolution benchmark。它直接测试 agent 是否能从一个 family 内的前序任务中抽取 skill patch、修复 skill、控制 library 膨胀，并迁移到同 family 后续任务。

### 哪些 skill 论文跑过

- `SkillFlow` 官方论文：主实验。

### 论文里的模型

- 项目页/摘要明确报告 `Claude Opus 4.6`、`Kimi K2.5`、`Qwen-Coder-Next`、`Qwen3-Coder-480B` 等配置。
- 每个模型在 no-skill / lifelong skill evolution 下比较 task completion 与 skill usage/utility。

### 普通 agent 做一题的自然工作流

1. 在一个 workflow family 中从空 skill library 开始。
2. 读取当前任务 instruction、环境文件和已有 skill。
3. 解决任务，运行测试或 verifier。
4. 根据成功/失败 trajectory 和 rubric 生成 skill patch。
5. 通过 `upsert_files/delete_paths` 更新 library。
6. 用更新后的 library 继续同 family 后续任务。

### 规模与划分

- `166` runnable Harbor tasks。
- `20` workflow families。
- `5` broad domains。
- 无普通 train/dev/test；核心划分是 family-local curriculum 和按难度排序的 sequential evaluation。不同 family 之间 library reset。
- HuggingFace dataset 约 `1.66 GB`，保留 `test_tasks/` 结构。

### 评分方式

- 任务 completion/pass rate。
- skill usage 与 skill utility 分析。
- patch 可审计性：每次 skill 更新都有 summary、`upsert_files`、`delete_paths`。

### 迁移适配判断

适合点：

- 和我们 B2 的“critic 输出 graph/skill signal，actor 生成 patch”非常接近。
- Family-local 顺序能更清楚地观察 skill 是否跨题复用。
- 任务新，直接服务 lifelong skill learning 主题。

主要阻塞：

- Harbor/container 依赖需要验证。
- 166 题全跑成本高，先选 2-3 个 family 做小闭环。
- 若官方 harness 对 skill patch 格式约束强，需要把我们当前 `SKILL.md`/phase graph 输出转换成它的 patch schema。

建议：

- 和 SkillsBench 并行做可运行性核对。若环境能顺利跑，作为第二主线，比 WebShop/ALFWorld 更贴当前方法。

## Benchmark Block 3：SkillLearnBench

### 基本定位

小规模 continual skill generation benchmark。强调“从 agent experience 自动生成 skill”是否提升真实 skill-dependent tasks。

### 哪些 skill 论文跑过

- `SkillLearnBench` 官方论文：主实验。

### 论文里的模型

- 摘要只说明比较 recent continual learning techniques、one-shot/self/teacher feedback、skill creator 等方法；具体 LLM 配置需要下载论文/代码进一步核对。

### 普通 agent 做一题的自然工作流

1. 从真实 skill taxonomy 选择一个 skill-dependent task。
2. agent 初始尝试任务。
3. skill learner 根据经验、反馈或 teacher signal 生成/改写 skill。
4. agent 带 skill 重试。
5. 同时评估 skill 文本质量、执行轨迹和最终结果。

### 规模与划分

- `20` verified tasks。
- `15` sub-domains。
- 传统 train/dev/test 未在摘要中明确；需要以开源 repo 为准。

### 评分方式

- skill quality。
- execution trajectory。
- task outcome。

### 迁移适配判断

适合点：

- 规模小，适合快速接入。
- 评估维度正好覆盖“skill 写得怎样、执行是否按 skill 走、最终是否成功”。
- 很新，主题聚焦 automatic skill generation。

主要阻塞：

- 论文和代码刚发布，工程成熟度待核对。
- 任务只有 20 个，容易过拟合；适合作为方法 smoke，不适合作唯一主线。

建议：

- 作为 P0 smoke 候选：先克隆 repo，确认 `uv`/Docker/测试入口，再决定是否纳入正式 pipeline。

## Benchmark Block 4：WebShop / ALFWorld / ScienceWorld 经典组

### 基本定位

交互式文本/网页环境。它们历史较早，仍被 2025-2026 skill/experience learning 论文频繁使用，是“别人论文里常见”的对齐组。

- `WebShop`：shopping web/text environment，目标是按用户约束搜索商品、筛选属性、购买。
- `ALFWorld`：text household environment，目标是操作房间、物体和 inventory 完成 household task。
- `ScienceWorld`：科学实验文本环境，目标是完成实验、观察、测量和推理。

### 哪些 skill 论文跑过

- `SkillRL`：`ALFWorld`、`WebShop`。
- `SkillNet`：`ALFWorld`、`WebShop`、`ScienceWorld`。
- `Self-Generated In-Context Examples`：`ALFWorld`。
- `ExpeL`：`ALFWorld`、`WebShop`。
- `EXIF` 本地旧调研记录：`WebShop`、`Crafter`。

### 论文里的模型

- `SkillNet` 摘要写 multiple backbone models，具体要看全文。
- `SkillRL` 摘要未列具体 backbone，强调 frozen/agent skill bank 与 RL。
- `Self-Generated In-Context Examples` 比较的是 agent 从成功轨迹中构造 examples，公开摘要给出 benchmark 提升。
- `ExpeL` 使用 GPT 系 API 时代模型，年份较早。

### 普通 agent 做一题的自然工作流

`WebShop`：

1. 读用户购物需求。
2. search 商品。
3. 逐页打开候选商品。
4. 核对属性、价格、约束。
5. 选择属性并 buy。
6. environment 返回 reward/success。

`ALFWorld`：

1. 读目标任务。
2. 观察房间状态和 inventory。
3. 输出文本动作，例如移动、打开、拿取、放置、清洗、加热。
4. 根据环境反馈修正。
5. 达成目标状态后 success。

`ScienceWorld`：

1. 读实验目标。
2. 观察环境、收集材料和仪器。
3. 执行动作、测量、比较。
4. 根据实验状态和任务要求给出完成动作。

### 规模与划分

- `WebShop`：标准协议需以 official repo 为准；本地已有 offline small text env，`human_small=13`、`attr_small=415`、smoke `3`。
- `ALFWorld`：常用公开协议约 `3.5k` train tasks，评估有 seen/unseen split；具体数量随 repo 版本和论文协议变化，落地前核对。
- `ScienceWorld`：30 个 task types，官方按 variation IDs 划分 train/dev/test，规模为多千 variations；落地前核对所用版本。

### 评分方式

- `WebShop`：reward / success rate。
- `ALFWorld`：success rate。
- `ScienceWorld`：task score / success，按 environment reward。

### 迁移适配判断

适合点：

- 和 skill/experience 论文对齐度高。
- 任务闭环干净，有明确 state/action/reward。
- `WebShop` 本地已有 adapter 雏形，可以先拿它打通状态机 action parser。

主要阻塞：

- 年份较早，单独使用会显得主线不够新。
- `WebShop` 正式环境依赖较重；本地 small 子集太小。
- `ALFWorld/ScienceWorld` 需要新接环境和动作协议。

建议：

- 作为“经典对齐组”保留。若 SkillsBench/SkillFlow 环境阻塞，优先用 `WebShop` 正式版或 `ALFWorld` 做替代主线。

## Benchmark Block 5：WebArena / BrowseComp / SealQA / OfficeQA 搜索浏览组

### 基本定位

这一组更接近 GAIA 的“题目驱动、多步证据、最终短答案”，但每个 benchmark 更聚焦。

- `WebArena`：真实网站交互 benchmark，浏览器动作、登录态、页面导航、表单/操作任务。
- `BrowseComp`：OpenAI 2025 发布的 browsing competition，`1,266` 个 hard-to-find short-answer questions。
- `SealQA`：search-augmented QA，在冲突、噪声、无用搜索结果中做事实问题。
- `OfficeQA`：企业文档/美国 Treasury Bulletin grounded reasoning，需要定位文档、表格和数字并计算。

### 哪些 skill 论文跑过

- `SkillWeaver`：`WebArena` 和 real-world websites。
- `EvoSkill`：`OfficeQA`、`SealQA`，并将 SealQA skill 迁移到 `BrowseComp`。
- `BrowseComp` 本身是 OpenAI browsing agent benchmark，也被 EvoSkill 用作 zero-shot transfer 评估。

### 论文里的模型

- `SkillWeaver`：web agent 设置，论文摘要未列全模型；强调 strong-to-weak skill transfer。
- `EvoSkill`：coding agent harness，摘要写 skill folders 可用于 Claude Code、Codex、OpenCode 等；公开摘要报告 Claude Code + Opus 4.5 配置需要后续全文核对。
- `BrowseComp` 官方评估包括 `GPT-4o`、`GPT-4.5`、`OpenAI o1`、`GPT-4o with browsing`、`Deep Research`。

### 普通 agent 做一题的自然工作流

`WebArena`：

1. 读目标。
2. 打开指定网站。
3. 观察 DOM/截图。
4. 点击、输入、导航、提交。
5. evaluator 判断目标状态或答案。

`BrowseComp/SealQA`：

1. 读短答案问题。
2. 生成搜索 query。
3. 浏览多个来源，处理冲突和噪声。
4. 记录证据链。
5. 输出短答案，按 exact match 或 judge/scorer 评分。

`OfficeQA`：

1. 读企业文档问题。
2. 检索和打开相关 Treasury Bulletin 文档。
3. 定位表格/图表/时间范围。
4. 抽取数字并用脚本计算。
5. 输出可验证数字或短答案。

### 规模与划分

- `WebArena`：官方常见规模 `812` tasks；需按本地复现 repo 核对。
- `BrowseComp`：`1,266` questions，无传统 train/dev/test；官方请求避免公开泄露样例。
- `SealQA`：有 `SEAL-0 / SEAL-HARD / LONGSEAL` flavors；规模需下载官方数据核对。
- `OfficeQA`：有 OfficeQA/OfficeQA Pro 相关版本；`OfficeQA Pro` GitHub 默认 benchmark `N=133`，EvoSkill 所用 OfficeQA 版本需另行核对。

### 评分方式

- `WebArena`：success rate，通常由任务 evaluator 判断。
- `BrowseComp`：短答案 exact match / equivalence scorer。
- `SealQA`：accuracy，按不同 flavor 统计。
- `OfficeQA`：exact match / numeric tolerance， grounded reasoning 输出可程序验证。

### 迁移适配判断

适合点：

- 这组最接近 GAIA 的“搜索/证据/答案”范式。
- `EvoSkill` 在 OfficeQA/SealQA 上给出了 skill evolution 的直接证据。
- `OfficeQA` 比 GAIA 更结构化，文档和数字链路适合写 procedural skill。

主要阻塞：

- `BrowseComp/SealQA` 仍会引入搜索 provider 和网页波动。
- `WebArena` 需要浏览器、网站服务、账号/状态环境。
- `OfficeQA` 文档处理可能依赖大 corpus，先要确认本地磁盘和下载来源。

建议：

- 第二阶段优先 `OfficeQA`，再考虑 `SealQA`。
- `BrowseComp` 用作 transfer/held-out 评估，不适合作为第一训练集。
- `WebArena` 与 SkillWeaver 对齐强，但工程成本高于 `WebShop`。

## Benchmark Block 6：Terminal-Bench / Harbor / SWE 类工程任务

### 基本定位

多文件、多命令、container verifier 的工程工作流 benchmark。和真实 coding agent/CLI agent 贴近。

### 哪些 skill 论文跑过

- `SkillsBench` 明确对比 Terminal-Bench：Terminal-Bench 评估原始模型和 harness 能力，SkillsBench 在此类 container/verifier 思路上评估 skill efficacy。
- 许多 coding agent work 使用 SWE-bench/Terminal-Bench；本轮 skill-specific 论文里，SkillsBench 是更直接的入口。

### 论文里的模型

- SkillsBench 覆盖 `Codex CLI + GPT-5.2`、`Claude Code`、`Gemini CLI`。
- Terminal-Bench/SWE-bench 的最新 leaderboard 会持续变化，正式横比前需要再次查官方榜。

### 普通 agent 做一题的自然工作流

1. 读任务说明。
2. 浏览文件树。
3. 编辑代码或脚本。
4. 运行测试。
5. 根据失败继续修。
6. verifier 通过记 success。

### 规模与划分

- 本地 `project_agent_skillrl_transfer` 已有 Terminal-Bench metadata 和 89 个任务 dry-run。
- 正式 Terminal-Bench 当前本机阻塞：Docker socket permission denied，Harbor command not found。
- SWE-bench/Verified 等规模随官方版本变化，需要单独核对。

### 评分方式

- deterministic tests / pass@k / success rate。

### 迁移适配判断

适合点：

- skill 对真实工作流帮助空间大。
- 和 `SKILL.md + scripts + tests` 的结构天然一致。

主要阻塞：

- Docker/Harbor 权限。
- 每题成本和运行时间大。
- 和当前 GAIA executor 工具链差异大，需要 coding agent harness。

建议：

- 通过 SkillsBench 间接切入。等 Harbor/Docker 跑通后，再把 Terminal-Bench 作为长期扩展。

## Benchmark Block 7：SQLBench / AgentBench DB / InterCode-SQL

### 基本定位

结构化数据库问答 / text-to-SQL / SQL execution benchmark。它非常干净，评分可程序化。

### 哪些 skill 论文跑过

- `Self-Generated In-Context Examples` 使用 `InterCode-SQL`。
- 本轮看到的 2026 显式 Agent Skills 论文对 `Spider/BIRD/AgentBench DB` 的使用频率低。

### 论文里的模型

- ICRL/self-generated examples 论文摘要未在 arXiv 页面列模型全表，需要全文核对。
- 本地当前可用模型可直接跑 9B executor 或 API model。

### 普通 agent 做一题的自然工作流

1. 读自然语言问题。
2. 读 schema 和 sample rows。
3. 写 SQL。
4. 执行 SQL。
5. 根据 SQL error 或 row shape 修复。
6. 提交最终 SQL/answer。

### 规模与划分

本地已经核对：

- Spider dev：`1034` 题。
- BIRD Mini-Dev SQLite：`500` 题。
- AgentBench DB：`db_dev=60`，`db_standard=300`，`db_out_new=4803`。

### 评分方式

- execution accuracy。
- 可记录 SQL error、empty result、wrong aggregation、wrong join 等错误类型。

### 迁移适配判断

适合点：

- 最干净、最快、可离线。
- 非常适合调状态机、repair loop、critic signal schema。

主要限制：

- 与 2026 Agent Skills 生态主线对齐度低。
- 工具调用空间窄，难展示复杂 skill composition。

建议：

- 保留为 smoke / unit benchmark。别把它作为“换 bench 后的主战场”。

## 最终推荐路线

### 阶段 0：先做可运行性核对，暂不启动正式实验

要核对三个 repo：

1. `benchflow-ai/skillsbench`
2. `SkillFlow` code + HuggingFace data
3. `cxcscmu/SkillLearnBench`

核对项：

- 是否需要 Docker/Harbor/BenchFlow。
- 是否能离线运行一个 oracle/verifier。
- skill 放置格式是否能接我们的 `SKILL.md`。
- 是否有 task subset / tag / difficulty 可抽样。
- 每题超时、磁盘占用、token 成本。

### 阶段 1：SkillsBench 作为第一主线

最小实验：

- 抽 `10` 个 task：优先 Core/Extended、verifier 快、依赖少。
- 三组条件：
  - no skill baseline。
  - 官方 curated skill。
  - 我们的 boot skill / actor skill。
- 记录：
  - pass/fail。
  - verifier failure。
  - 是否读取 skill。
  - skill 中哪个模块被使用。
  - token 和 wall time。

目标：

- 先确认我们的 skill 生成格式能被 agent 利用。
- 对比官方 curated skill，避免只和 no-skill 比。

### 阶段 2：SkillFlow 做 lifelong skill patch

最小实验：

- 选 2 个 workflow family，每个 family 前 3-5 题。
- 从空 skill library 开始。
- 用当前 critic/actor 生成 patch。
- 每题后评估 library 是否变大、是否被使用、是否提升后续题。

目标：

- 把现在 B2 没真正改图的问题迁到一个更适合 patch 的 benchmark。
- 观察 skill patch 是否能跨同 family 复用。

### 阶段 3：经典组补对齐

若需要和老牌经验学习论文横比：

- `WebShop` 先行，因为本地已有 partial adapter。
- `ALFWorld` 第二，因为论文使用频率高、success rate 清楚。
- `ScienceWorld` 第三，接入成本略高。

### 阶段 4：搜索/证据组展示 GAIA 类能力

若 SkillsBench/SkillFlow 已有结果，再迁到：

- `OfficeQA`：优先，结构化文档和计算更干净。
- `SealQA`：检索噪声更强，适合测试 search persistence skill。
- `BrowseComp`：作为 zero-shot transfer / held-out browsing benchmark。

## 对当前项目的直接决策

- `GAIA` 保留为历史对照和负例分析，不继续作为主提分 bench。
- `/data/xsy/project_agent_skillrl_transfer` 的 SQL/tau/WebShop adapter 继续有价值，但第一目标应改成 SkillsBench/SkillFlow 的可运行性验证。
- `SQLBench/AgentBench DB` 只承担 smoke 和快速回归。
- 新分支建议从 GAIA 当前分支或独立 transfer repo 起，名字可用 `codex/skillbench-transfer-skillsbench`。
- 新 benchmark 的 skill 不要硬套 GAIA 七阶段。每个 benchmark 先按自然工作流写 domain-specific phase，再决定是否需要状态图。
