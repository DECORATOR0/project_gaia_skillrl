## 当前可采纳的结论

1. ARCH-V4 runtime 反馈值得保留。
   bootstrap dev/test 都有小幅改善，空答保持在较低区间。
2. A_full test `20/79` 是本轮最值得跟进的信号。
   它相对 bootstrap test 有 9 个新增正确，且新增主要来自数值、实体、访问失败恢复，不只是 tail 缺口造成的分母变化。
3. A_full skill 暂时不能直接升为稳定配置。
   A_full dev 只有 `15/80`，实体错配从 bootstrap dev 的 20 个增加到 25 个。
4. B_sharded 的收益更像题型局部收益。
   B_dev 减少了数值错，但空答上升；B_test 减少了访问失败式作答，但列表错误上升。
5. 三路成功集合有互补性。
   test 三路并集 `25`，A_full 单路 `20`；dev 三路并集 `26`，三路交集只有 `5`。后续可以考虑按题型路由或 critic 选择，而非只追一个全局 skill。

## 下一步优化优先级

### P0：补 A_full test 的确认实验

目标：确认 `20/79` 是稳定增益。

- 用同一个 A_full skill 补跑 test tail 缺口 3 题，或直接完整重跑 test82。
- 保留同样 executor endpoint 和并发，避免 serving 差异混进判断。
- 同时记录 A_full test 的 9 个新增正确和 4 个丢失正确是否复现。

### P1：候选缓存与低步数收口

目标：减少 A/B 后 invalid action 总量带来的空答。

- 运行时缓存所有被拒绝的 non-CONCLUDE `<ANSWER>`。
- 剩余步数 `<=3` 且已有候选时，强制引导到合法收口路径。
- 对 `REPAIR` 工具调用次数加硬限制，超过 2 次后必须 `VERIFY` 或 `CONCLUDE`。
- 在 bootstrap prompt 或 skill 后处理里恢复窄条件 `REPAIR -> CONCLUDE` 与 `WEB_EVIDENCE -> CONCLUDE`。

### P2：数值题专项

目标：最大错误桶仍是数值 / 计数 / 单位。

- 数值题进入 `COMPUTE` 时强制列出：数据来源、筛选范围、公式、单位、最终格式。
- 需要算术、计数、日期差、表格聚合时优先调用 `run_python` 或表格工具。
- `CONCLUDE` 前检查单位尺度、百分比、货币、日期格式和小数位。

### P3：实体和证据定位专项

目标：修 A_full dev 的实体错配上升，以及 A_full test 丢失的证据定位样本。

- `VERIFY` 阶段强制回读题目 ask target：人物、字段、年份、标题、类别、数值。
- 搜索结果只做定位线索，最终答案要来自 fetch 内容、本地文件或明确结构化证据。
- 对同名实体、论文标题、作品名、媒体任务增加 disambiguation 步骤。

### P4：多项答案集合校验

目标：控制 B_sharded test 的列表 / 集合错误。

- 多项题强制核对元素数、去重、排序、大小写、分隔符。
- 对 `all / both / countries / names / colors` 这类提示词触发集合校验。
- 输出前把候选集合和题目约束逐条对齐。

## 收尾判断

这轮结果比单看 bootstrap 更有信息量。ARCH-V4 是有效的小修，A_full test 是有价值的正信号，A/B skill 仍存在 split 方差和协议噪声。下一轮最稳的路线是保留 ARCH-V4，先确认 A_full test 增益，再把候选缓存、低步数收口、数值题专项和实体核验接上。
