# 26.4.19_2332_GAIA工具全集本地化建设计划

## 1. 目标

给 `project_gaia_skillrl` 落一套可持续扩展的 `GAIA toolbox`，覆盖常见题型和常见模态，满足下面四条约束：

- 运行时只要求提供一个 `OpenAI` 兼容模型 API。
- 搜索、文件解析、OCR、音频转写、浏览器、代码执行等能力尽量走本地代码和本地依赖。
- 不依赖 `Tavily / Exa / E2B / Steel / Mem0 / AssemblyAI` 这类第三方 SaaS key。
- 保留当前项目结构，继续以 `gaia_skillrl/tools.py` 这一层做统一工具注册和调度入口。

这份文档给后续执行 AI 直接用。目标是先把“工具全集”建起来，再谈更复杂的 skill 训练。

## 2. 当前基线

当前全局工具全集只有 9 个，定义在 [tools.py](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:90) 到 [tools.py](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:170)：

- `list_dir`
- `read_file`
- `read_json_file`
- `extract_pdf_text`
- `read_table`
- `image_metadata`
- `web_search`
- `fetch_url`
- `run_python`

这套工具适合：

- 纯文本题
- 简单网页检索题
- PDF 文本抽取题
- 表格题
- 一部分数值计算题

当前明显缺口：

- `mp3 / wav / m4a` 音频题无解，缺少转写链路
- `png / jpg` 图片题只有元数据，没有 `OCR` 和图像问答
- `docx / pptx` 没有专用解析
- `zip / tar / 多附件` 没有专门解包和清单整理
- 动态网页和交互网页缺少浏览器能力
- HTML 正文抽取偏弱，`fetch_url` 还是整页抓取

## 3. 参考结论

外部材料可以分成两类：

- `AutoGen / Magentic-One`：适合参考 agent 编排、browser、file、code executor 的组织方式
- `Memento`：适合参考 GAIA 工具覆盖面，尤其是文档、图像、视频、音频这类模态

这次建设建议采用下面的策略：

- 架构保持当前项目自己的单 executor 体系
- 工具覆盖面参考 `Memento`
- 浏览器和执行层的组织方式参考 `AutoGen / Magentic-One`
- 不直接照搬任何外部仓库

## 4. 目标工具全集

### 4.1 核心保留

这 9 个工具继续保留，作为基线能力：

- `list_dir`
- `read_file`
- `read_json_file`
- `extract_pdf_text`
- `read_table`
- `image_metadata`
- `web_search`
- `fetch_url`
- `run_python`

### 4.2 第一批必须补齐

这一批直接决定 GAIA 的覆盖率，优先级最高。

- `audio_transcribe`
  - 输入：本地音频路径，可选语言、可选返回时间戳
  - 输出：纯文本转写结果，可选分段信息
  - 目标：覆盖 `mp3 / wav / m4a / ogg`
- `ocr_image`
  - 输入：本地图片路径，可选语言
  - 输出：识别文本，必要时返回 bbox
- `image_qa`
  - 输入：本地图片路径 + 问题
  - 输出：简短答案
  - 备注：如果本地视觉模型链路太重，第一阶段可以先只做 `ocr_image`
- `parse_docx`
  - 输入：本地 `docx` 路径
  - 输出：正文、标题、表格摘要
- `parse_pptx`
  - 输入：本地 `pptx` 路径
  - 输出：按页展开的文本、备注、图片占位信息
- `extract_archive`
  - 输入：本地压缩包路径
  - 输出：解压目录、文件清单、可选递归清单
- `html_extract`
  - 输入：URL 或本地 html 路径
  - 输出：正文文本、标题、链接摘要

### 4.3 第二批强烈建议补齐

这一批会明显提升稳定性和题型上限。

- `browser_open`
- `browser_click`
- `browser_extract`
- `browser_screenshot`
- `video_sample`
  - 输入：视频路径
  - 输出：抽帧图片路径、时间点清单
- `video_transcribe`
  - 输入：视频路径
  - 输出：音轨转写文本
- `spreadsheet_advanced`
  - 输入：表格路径 + 指令
  - 输出：聚合、过滤、透视后的结构化结果
- `answer_format_check`
  - 输入：题目要求 + 候选答案
  - 输出：格式检查和收束建议

### 4.4 当前阶段可以暂缓

- `memory`
- 多 agent 协作
- 第三方 SaaS provider 适配
- 长期会话状态存储

## 5. 建议的本地依赖

原则很明确：只要求一个模型 API。其余能力尽量靠本地依赖完成。

### 5.1 Python 依赖

- `faster-whisper`
- `ffmpeg-python`
- `pytesseract`
- `easyocr`
- `python-docx`
- `python-pptx`
- `trafilatura`
- `readability-lxml`
- `openpyxl`
- `xlrd`
- `python-magic`
- `rarfile`
- `pymupdf`
- `pdfplumber`

### 5.2 系统依赖

- `ffmpeg`
- `tesseract-ocr`
- `poppler-utils`
- `libmagic`
- `unrar` 或兼容解压工具
- `chromium` 或 `playwright` 所需浏览器

### 5.3 依赖选择建议

- 音频转写优先用 `faster-whisper`
  - 原因：本地可跑，接口简单，适合作为统一工具底座
- OCR 先走 `tesseract + pytesseract`
  - 对中文或复杂图像效果不足时，再加 `easyocr`
- 文档解析优先走轻量专用库
  - `docx -> python-docx`
  - `pptx -> python-pptx`
  - `pdf -> pypdf + pymupdf + pdfplumber`
- 网页正文抽取优先用 `trafilatura`
- 浏览器能力优先用本地 `playwright`

## 6. 工具接口设计原则

所有工具都建议遵守当前 `ToolSpec` 体系，保持三个统一约束：

1. 输入尽量是简单 JSON 参数
2. 输出尽量返回结构化字典
3. 错误信息要显式可见，便于 agent 继续决策

建议新增工具返回统一字段：

- `ok`
- `path`
- `content`
- `metadata`
- `warnings`
- `error`

示例：

```json
{
  "ok": true,
  "path": "/abs/path/file.mp3",
  "content": "transcribed text ...",
  "metadata": {
    "language": "en",
    "segments": 12
  },
  "warnings": []
}
```

## 7. 题型到工具的覆盖映射

### 7.1 音频题

典型链路：

`list_dir -> audio_transcribe -> run_python -> final answer`

覆盖目标：

- 找页码
- 找数字
- 找人名地名
- 找音频里读出的段落内容

### 7.2 图片题

典型链路：

`image_metadata -> ocr_image -> image_qa -> final answer`

覆盖目标：

- 海报题
- 截图题
- 含数字或表格的图片题

### 7.3 文档题

典型链路：

`parse_docx / parse_pptx / extract_pdf_text -> run_python -> final answer`

覆盖目标：

- 报告文档
- 演示文稿
- 混合文本和表格的附件题

### 7.4 多文件题

典型链路：

`extract_archive -> list_dir -> read_file / read_table / parse_docx -> run_python`

覆盖目标：

- 压缩包
- 附件目录遍历
- 多来源证据合并

### 7.5 网页题

典型链路：

- 简单网页：`web_search -> fetch_url / html_extract`
- 动态网页：`browser_open -> browser_click -> browser_extract`

## 8. 实施顺序

### Phase 0：统一规划

目标：

- 明确工具名和 schema
- 明确新增依赖
- 明确 smoke 数据集

产出：

- 本文档
- 一份依赖安装清单
- 一份 smoke 任务清单

### Phase 1：补齐本地静态解析能力

范围：

- `audio_transcribe`
- `ocr_image`
- `parse_docx`
- `parse_pptx`
- `extract_archive`
- `html_extract`

代码落点建议：

- [tools.py](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:1)
- 需要时新建 `gaia_skillrl/tool_helpers/`

验收标准：

- 以上工具都能单独调用
- 都有最小单测或最小 smoke 脚本
- 工具报错可读

### Phase 2：补齐动态网页和高级表格能力

范围：

- `browser_open`
- `browser_click`
- `browser_extract`
- `browser_screenshot`
- `spreadsheet_advanced`

验收标准：

- 能处理至少一题需要网页点击的样例
- 表格聚合题能稳定调用到高级表格工具

### Phase 3：把 skill 和 prompt 路由补上

范围：

- 更新 bootstrap skill prompt
- 更新 actor prompt
- 增加对新模态的路由提醒
- 减少“遇到不支持模态就直接放弃”的行为

相关文件：

- [bootstrap_skill_system.md](/data/xsy/project_gaia_skillrl/prompts/bootstrap_skill_system.md:1)
- [actor_system.md](/data/xsy/project_gaia_skillrl/prompts/actor_system.md:1)

验收标准：

- 新工具出现在 tool prompt 中
- skill 文档会提醒音频、图片、文档、压缩包等附件处理路径

### Phase 4：小批量 GAIA smoke

建议 smoke 集至少包含：

- 1 道音频题
- 1 道图片 OCR 题
- 1 道 `docx/pptx` 题
- 1 道压缩包多文件题
- 1 道动态网页题
- 1 道纯 text/web 对照题

验收标准：

- 工具调用链真实发生
- 中间结果可检查
- 至少有一部分原来无解的题型变成可解

## 9. 给执行 AI 的直接任务单

后续执行 AI 建议按这个顺序做：

1. 先安装本地依赖，优先安装 `ffmpeg`、`tesseract-ocr`、`faster-whisper`、`python-docx`、`python-pptx`、`trafilatura`
2. 在 [tools.py](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:1) 注册第一批新增工具
3. 给每个新增工具写最小 smoke 脚本
4. 选 5 到 6 道覆盖不同模态的 GAIA 题做小批量验证
5. 再更新 skill prompt 和 actor prompt

执行过程中优先遵守这几条：

- 只新增，不删当前 9 工具
- 工具名保持简洁稳定
- 参数 schema 保持 JSON 友好
- 先求能跑通，再做质量优化

## 10. 本轮建议定稿结论

当前最合理的路线是：

- 继续沿用 `project_gaia_skillrl` 作为主干
- 把 `Memento` 当作工具覆盖参考
- 把 `AutoGen / Magentic-One` 当作浏览器与执行层参考
- 由本项目自己落地一套本地优先的 `GAIA toolbox`

只要这条路线执行到位，后面你提供一个 `OpenAI` 兼容模型 API 就够了，其余能力都可以收敛到本地代码层。
