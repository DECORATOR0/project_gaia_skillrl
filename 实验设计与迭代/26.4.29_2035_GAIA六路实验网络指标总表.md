- 完整六路指 `boot_dev`、`boot_test`、`A_dev`、`A_test`、`B_dev`、`B_test` 都已经跑过的实验组。
- 运行中六路快照会临时列在聚合总览末尾，并在备注里标出未完成 lane；最终数值以后续收口快照为准。
- `start` 精确到分钟，用实验组第一条正式评测启动时间；如果 boot 和 AB 分段恢复，备注里写出恢复时间。
- `states` 为已产出状态数 / 目标题数。`success` 为 evaluator 通过数。
- `empty` 为最终空答案或未形成非空答案的状态数。
- `invalid broad` 为协议摩擦总量，覆盖 `invalid_answer_phase`、phase transition / tool allowlist / action parse 类失败。
- `invalid_answer_phase` 单列，用来观察 answer phase 相关回潮。
- `web succ/fail` 只统计 `web_search` 调用成功 / 失败。`timeout` 和 `403` 是 `web_search fail` 的子类，`web external states` 是受 timeout、403、连接错误、botcheck、429 等影响的去重题次。
- `fetch/html fail` 单独统计 `fetch_url` 与 `html_extract` 抓取层失败，不并入 `web_search fail`。
- 本表的 `timeout calls/states` 仅指 `web_search` 工具内部的 DDG/HTML fallback 访问超时，典型错误为 `HTTPSConnectionPool(host='html.duckduckgo.com', port=443): Read timed out. (read timeout=30)`。它不统计本地 executor/vLLM 的 streaming wall timeout、empty content retry、队列等待或模型服务 readiness timeout。
- `exec fatal c/s` 统计 executor/vLLM 层最终耗尽重试并抛出的 fatal LLM 调用，例如 `Streaming response exceeded wall timeout` 或 `Streaming response produced empty content` 在 6 次尝试后仍失败。`calls` 为 fatal LLM 调用次数，`states` 为被该 fatal 直接打断的题次；普通 retry warning 后续成功的情况未计入。
