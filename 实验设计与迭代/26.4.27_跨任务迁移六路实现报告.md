## 4. Task -> Adapter -> Phase Trace -> Score 工作流

### AgentBench DB / OS

- Task: DB 从 JSONL 读取 question、table_info、official SQL / label；OS 从 dev JSON 读取 instruction、checker、Docker image。
- Adapter: `AgentBenchAdapter` 映射到统一 `BenchmarkTask`，DB 构建 in-memory SQLite，OS 构建 dry-run checker metadata。
- Phase trace: `INIT` 读题和 suite，`INSPECT` 输出 schema / checker，`PLAN` 选 SQL 或 shell/checker 路径，`EXECUTE` 执行 SQL 或生成 OS workspace plan，`VERIFY` 比较 label 或记录 checker 状态，`CONCLUDE` 输出 score。
- Score: DB 用 normalized SQL execution answer 对齐 label；OS 当前 dry-run 成功记录为 scaffold success，score 0.0。

### tau2 retail / airline

- Task: 读取 domain task、policy、tools、db、split membership。
- Adapter: `TauBenchAdapter` 生成 domain prompt，并用 upstream helper 子进程执行官方 expected actions。
- Phase trace: `INIT` user scenario，`INSPECT` policy / tools / split，`PLAN` oracle action replay，`EXECUTE` upstream tau2 env tool calls，`VERIFY` DB/ACTION/COMMUNICATE reward，`CONCLUDE` 写 reward breakdown。
- Score: retail task 0 与 airline task 1 均为 1.0；NL assertion LLM judge 当前跳过。

### Terminal-Bench 2.0

- Task: 从官方 task repo 读取 `instruction.md`、`task.toml`、environment、tests。
- Adapter: `TerminalBenchAdapter` 复制 dry-run workspace，记录 Docker image、test command、Harbor checker 元信息。
- Phase trace: `INIT` task id / difficulty，`INSPECT` environment and tests，`PLAN` workspace/checker plan，`EXECUTE` 复制 workspace 和 RUNBOOK，`VERIFY` dry-run 或 checker diagnostics，`CONCLUDE` 写 result。
- Score: 5 题 dry-run scaffold success，score 0.0；`fix-git` checker attempt 因 Docker socket 和 Harbor 缺失 blocked。

### BrowserGym MiniWoB

- Task: MiniWoB env id、HTML path、description。
- Adapter: `BrowserGymAdapter` 在 Python 3.12 venv helper 子进程中执行 Gymnasium reset/step。
- Phase trace: `INIT` env id / seed，`INSPECT` MiniWoB URL / observation keys，`PLAN` heuristic action，`EXECUTE` env.step，`VERIFY` reward / terminated / action error，`CONCLUDE` 写 score。
- Score: 5 个 MiniWoB 轻任务 reward 均为 1.0。

### SQLBench Spider / BIRD

- Task: question、schema、SQLite db path、evidence、gold SQL。
- Adapter: `SQLBenchAdapter` 读取 Spider / BIRD 数据，执行 SQLite schema inspect 和 SQL execution。
- Phase trace: `INIT` dataset/db/question，`INSPECT` tables/columns/sample rows，`PLAN` oracle SQL，`EXECUTE` gold and candidate SQL，`VERIFY` normalized rows，`CONCLUDE` execution accuracy。
- Score: 5 题 execution accuracy 均为 1.0。

### WebShop text mode

- Task: instruction、target ASIN、product query、required attributes、required options。
- Adapter: `WebShopAdapter` 读取 1000-product preview 和 instruction/attribute 文件，启动轻量 text session。
- Phase trace: `INIT` instruction/session，`INSPECT` text observation / available actions，`PLAN` action chain，`EXECUTE` `search[...]`、`click[...]`、`select[...]`、`buy now`，`VERIFY` reward/done/constraints，`CONCLUDE` purchase trace。
- Score: 3 条 instruction 均 reward 1.0，覆盖无 option、单 option、双 option。

## 6. 切正式实验需要改的配置

- 模型：等 38B API 到位后，将 executor / critic / actor 模型、base URL、API key 写入统一配置；当前 SSS AI `gpt-5.2` 仅保留 1-3 题 smoke 用途。
- 并发：从 `c1-c3` smoke 起步，确认各 benchmark 环境稳定后再扩大；Terminal / Browser / WebShop native 先单进程。
- 步数：沿用统一 phase graph 的 `INIT / INSPECT / PLAN / EXECUTE / VERIFY / REPAIR / CONCLUDE`，每题先限制短步数，长任务单独提升。
- 数据 split：AgentBench 用 DB dev / OS dev；tau 用 retail/airline train/test；Terminal 用 smoke subset 后再扩；BrowserGym 用 MiniWoB smoke/all；SQLBench 用 Spider dev / BIRD mini-dev；WebShop 先 small preview，再切 full data。
- 环境：Docker、Harbor、BrowserGym venv、WebShop Lucene index、BIRD DB runtime 全部写入 manifest 后再启动正式队列。
- 运行规范：任何后台正式队列都使用 `nohup` 和 `runs/_launch_logs/`，并更新 `/data/xsy/活的进程.csv`。
