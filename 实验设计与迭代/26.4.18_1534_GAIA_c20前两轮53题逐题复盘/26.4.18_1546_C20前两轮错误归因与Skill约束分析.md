## 先给结论

- 这组 run 已经形成了稳定闭环，主矛盾落在 executor 的解题质量。
- 自动机的形式完成率其实很高：两轮都是 `50/53` 题走到了 `INIT -> GATHER -> ANALYZE -> CONCLUDE`。失败题里，iteration_01 也有 `37/40`，iteration_02 有 `39/42` 走完了完整 phase path。

## 具体错误模式

### 1. 取错字段 / 格式尺度不对

- 主因计数：iteration_01 9 题，iteration_02 12 题。
- 这类题的共同点是 evidence 大方向接近，最终字符串落错了字段、尺度、格式或精确文本。
- [iter1-earthmoon](iteration_01/task_01_e1fc63a2.md)：算的是 17 thousand-hours，却应该输出 17000。
- [iter1-drwho](iteration_01/task_07_4b6bb5f7.md)：问 first scene heading，答成 episode title。
- [iter2-city](iteration_02/task_48_bda648d7.md)：gold 要 Saint Petersburg，模型给了缩写 St. Petersburg。
- [iter1-grocery](iteration_01/task_30_3cef3a44.md)：字段和输出格式都混在一起，答案串不干净。
- 这类问题说明 skill 里“check units/format/exact wording”已经写进去了，executor 在 ANALYZE 里没有真正把目标字段 schema 结构化下来，只是凭近似语义直接落答案。

### 2. 推理或事实判断错误

- 主因计数：iteration_01 11 题，iteration_02 14 题。
- 这类题很多已经完整走完 phase path，失败点已经从流程转向 reasoning 本身。
- [iter1-reverse](iteration_01/task_09_2d83110e.md)：反向指令题理解错了 opposite of left。
- [iter1-mw](iteration_01/task_20_5188369a.md)：Merriam-Webster 引文题把 quoted writer 认成了页面作者。
- [iter2-malko](iteration_02/task_53_5a0c1adf.md)：Malko 题在信息不扎实时仍然硬猜 Viktor。
- [iter2-tizin](iteration_02/task_15_42576abe.md)：自造语言题语义规则没解对。
- 这部分最难靠继续堆 skill 文案解决，因为它需要 executor 真正做语义判别、规则求解和事实区分。

### 3. 附件工具覆盖不足

- 主因计数：两轮都是 9 题。
- 当前工具链只支持：文本读取、PDF 文本抽取、表格 preview、图片 metadata、网页搜索抓取、短 Python。
- 代码上可以直接看到：[read_table](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:226)、[image_metadata](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:243)、[fetch_url](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:303)、[run_python](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:324)。这里没有音频转写、OCR、PPTX/DOCX 内容抽取、棋盘/图像理解。
- `.xlsx` 虽然能过 `read_table`，当前实现只给 dataframe preview，题目一旦依赖单元格颜色、空间布局、跨 sheet 关系、公式结果或更长表格上下文，信息就会断层。
- [iter1-docx](iteration_01/task_08_cffe0e32.md)：Secret Santa 题需要读 .docx，当前工具链没有 docx parser。
- [iter1-mp3](iteration_01/task_31_99c9cc74.md)：购物清单音频题，mp3 无法转写，后面开始在 phase 上空转。
- [iter2-png](iteration_02/task_17_cca530fc.md)：棋局图题只拿到 image metadata，根本没有棋盘内容。
- [iter2-xlsx](iteration_02/task_52_7bd855d8.md)：销售表题需要更完整的表格语义，read_table 只给 preview。

### 4. 证据不足后保守收尾或猜答

- 主因计数：iteration_01 6 题，iteration_02 5 题。
- 这类题的 executor 往往已经感知到证据不够，最后还是以 `Unable to determine`、`Information not available` 一类字符串结束，或者半猜一个附近答案。
- [iter1-base](iteration_01/task_14_72e110e7.md)：证据不够后直接输出 Unable to determine。
- [iter2-lli](iteration_02/task_39_7673d772.md)：网页片段不足，最终收成 Unable to determine。
- [iter2-enroll](iteration_02/task_47_a0068077.md)：临床试验 enrollment 题收成 Information not available。
- 这一类相较 iteration_01 略有收缩，说明后两版 skill 在“不要太早宣称无法确定”上有一定效果。

### 5. 自动机崩溃 / 阶段控制失效

- 主因计数：iteration_01 5 题，iteration_02 2 题。
- 这类题是“看起来没有把自动机走完”的核心样本。它确实存在，数量已经降到少数。
- [iter1-maxstep](iteration_01/task_02_8e867cd7.md)：Mercedes Sosa 题直接耗尽 12 步，没有最终答案。
- [iter1-riddle](iteration_01/task_03_ec09fa32.md)：riddle 题在 ANALYZE 里反复提前 ANSWER。
- [iter2-bob](iteration_02/task_37_e142056d.md)：Bob game show 题长时间停在错误 phase，最后 max steps reached。
- 这一类的下降很明显，说明 skill 对表层 phase 行为是有效的。它解决了小头，大头已经是“走完自动机之后还是答错”。

## Skill 两次改写到底带来了什么

### iteration_01 actor 之后

- 参考：[iteration_01 before_actor](/data/xsy/project_gaia_skillrl/runs/2026/4/2026-4-18/20260418_130731_gaia_validation53_level1_train2_qwen3_8b_gpt54_c20/iteration_01/skill_before_actor/gaia-general-skill/SKILL.md) / [iteration_01 after_actor](/data/xsy/project_gaia_skillrl/runs/2026/4/2026-4-18/20260418_130731_gaia_validation53_level1_train2_qwen3_8b_gpt54_c20/iteration_01/skill_after_actor/gaia-general-skill/SKILL.md)
- INIT 被写得更窄：只允许识别 manifest 和附件名，强调不要在 INIT 用提取工具或 web。
- GATHER 新增 extension-aware retrieval、二进制文件禁用 `read_file`、403/空页面时换源。
- ANALYZE 新增 output schema、exact wording、不要 pattern match、证据不足就回 GATHER。
- CONCLUDE 新增 exact entity / exact wording 检查。

### iteration_02 actor 之后

- 参考：[iteration_02 after_actor](/data/xsy/project_gaia_skillrl/runs/2026/4/2026-4-18/20260418_130731_gaia_validation53_level1_train2_qwen3_8b_gpt54_c20/iteration_02/skill_after_actor/gaia-general-skill/SKILL.md)
- 新增“不要答邻近字段”的约束，明确写了 scene heading vs episode title、species vs generic class、city-only vs city+state。
- 新增 attachment/media fallback checklist。
- ANALYZE 新增 answer type 分类和 puzzle/formal-language 显式解析要求。
- CONCLUDE 新增“如果 final string 任何一部分无法 justify，就回 GATHER/ANALYZE”。

### 实际效果

- 这些改写确实让 executor 少犯了几类显式违规：提前 ANSWER、非法 NEXT、错误工具调用都下降了。
- 这些改写没有把“精确字段选择”和“高难语义推理”稳定拿下。accuracy 反而从 13/53 掉到 11/53。
- 所以当前 skill 的作用更像“软约束行为清洁剂”，离“强制收敛到正确自动机语义”还有明显距离。

## 为什么 skill 没把自动机真正压实

1. phase graph 和 phase tool allowlist 是 runtime 硬编码的，skill 只能改自然语言说明，改不了执行机制本身。参考 [_build_phase_transition_graph](/data/xsy/project_gaia_skillrl/gaia_skillrl/environment.py:74) 和 [_build_phase_tool_allowlist](/data/xsy/project_gaia_skillrl/gaia_skillrl/environment.py:92)。
2. 违规处理走的是“先输出，再驳回”的路径。executor 会先输出 `<ANSWER>` 或非法 `<NEXT>`，runtime 才回一个 feedback 让它再来。参考 [answer branch](/data/xsy/project_gaia_skillrl/gaia_skillrl/agent_loop.py:377) 和 [next branch](/data/xsy/project_gaia_skillrl/gaia_skillrl/agent_loop.py:498)。
3. 每次工具返回后，runtime 给的提示非常通用，只说“证据够了就进下一 phase”，没有把这道题还没满足的 checklist 结构化保存下来。参考 [_phase_runtime_instruction](/data/xsy/project_gaia_skillrl/gaia_skillrl/agent_loop.py:250) 和工具结果回注 [step message](/data/xsy/project_gaia_skillrl/gaia_skillrl/agent_loop.py:485)。
4. `remaining_steps <= 3` 时会自动 fallback conclude，把 executor 从 ANALYZE 推到 CONCLUDE。这个机制能避免无穷拖延，也会制造“最后补手续”的观感。参考 [fallback conclude](/data/xsy/project_gaia_skillrl/gaia_skillrl/agent_loop.py:343)。
5. 附件工具覆盖范围本身不够，很多题在 GATHER 阶段就拿不到有效证据，后面的 phase 只能围绕残缺 observation 转。参考 [tools.py](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:206)。
- 这五点叠在一起之后，skill 能做到“告诉模型该怎么做”，做不到“保证模型已经真的做到了”。

## 当前还剩的系统层噪声

- [task_35_f918266a](iteration_01/task_35_f918266a.md) 暴露出一个小的 runtime 误报：`read_file` 读 Python 源码时，正文里有 `Exception`，会被 `_SEMANTIC_FAILURE_MARKERS` 误判成失败调用。参考 [_SEMANTIC_FAILURE_MARKERS](/data/xsy/project_gaia_skillrl/gaia_skillrl/agent_loop.py:18) 和 [_extract_semantic_failure](/data/xsy/project_gaia_skillrl/gaia_skillrl/agent_loop.py:91)。

## 建议

1. 如果目标是把自动机真正压实，下一步应该把“是否已经满足 conclude 条件”做成结构化状态。继续堆自然语言 skill 的收益已经很有限。
2. 如果目标是提分，优先级更高的是补附件工具链：音频转写、OCR/图像内容、PPTX/DOCX 抽取，以及更完整的表格语义。
3. 对开放网页题，建议在 ANALYZE 前强制落一个 machine-readable answer schema，例如 `answer_type / target_field / exact_format / source_span / transform_rule`。
4. 统计层面建议把 `hard fail` 和 `semantic degraded` 拆开，不然 read_file 这类误报会把训练反馈带偏。
