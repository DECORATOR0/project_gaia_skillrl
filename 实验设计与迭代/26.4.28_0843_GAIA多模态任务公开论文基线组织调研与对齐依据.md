## 本文问题

本文只聚焦三个问题：

1. 公开论文里，`Qwen3-8B` 或 7B/8B 级开源小模型跑 GAIA / deep search / 多跳人物题时，下游范式通常怎么设置。
2. 本项目 aligned local direct run `13/81` 低于若干公开 `18-23` 左右 vanilla agent baseline，是否能从工具后端差异和错题中找到证据。
3. skill / skill-library 论文里，no-skill、same-harness empty-library、with-skill 三类条件应如何映射到本项目。

## 结论

公开工作里的小模型 GAIA baseline 通常就是固定工具 ReAct / tool-use agent：

```text
Qwen3-8B policy
+ fixed tool suite
+ structured tool_call / tool_response loop
+ max step / max token / scorer
+ final answer
```

它们会把 8B 放进一个受控多步工具环境里，限制工具、格式、步数和最终答案协议。这个范式和本项目当前 `Qwen3-8B-local + direct ReAct executor + GAIA toolbox + scorer` 基本一致。

本项目 `13/81` 低于 Reagent full-GAIA `20.0`、ToolSelf Vanilla Agent `18.8/19.7`、ARPO ReAct `23.3`，更可能来自工具后端和服务工程差异；baseline 范式本身已和公开工作对齐。尤其是搜索/浏览链路：

- 公开工作多用 Bing Search API、Jina Reader、LLM summarizer、GPT-4.1 image caption、Whisper-large-v3。
- 本项目当前 web search 是 `duckduckgo_search/DDGS` 免费层级；fetch 是 `requests + BeautifulSoup` 原始文本截断；PDF URL 用 `fetch_url` 时会返回 raw PDF bytes；网页历史、Wayback、动态站点处理较弱。
- `13/81` run 中，web-related 题 `5/46 = 10.9%`，non-web 题 `8/35 = 22.9%`。web 相关题明显更拖后腿。

因此，对外表述建议是：

> We follow the common small-model GAIA setup by evaluating Qwen3-8B as a controlled fixed-tool ReAct agent. The remaining gap to public Qwen3-8B GAIA baselines is plausibly attributable to retrieval and browsing backends: public systems use Bing/Jina/LLM-assisted browser tools, while our current run uses a local free search stack and raw page fetching.

2026-04-28 更新决策：

- 短期主线回到 `TOOL-GAIA-V2 / atomic_v2`，也就是此前 `13/81` 使用的十六原子工具形态。
- `TOOL-GAIA-V3 / reagent_facade_v3` 作为 Reagent 对齐分支保留。当前免费/本地平替版 no-skill direct 为 `9/82`，低于 V2 的 `13/81`。
- 这次 V3 结果说明六工具标签本身可复刻，但 Reagent 分数依赖厚工具实现。缺 API search、Jina Reader、LLM 页面总结、强 VLM/Whisper 时，工具路由简化不足以抵消 search/browse/media 后端质量损失。
- 后续若要重启 V3，先补强 `search/browse` 后端，再跑同一 `validation_test82` 与 V2 做 A/B。

## 公开论文范式

### 1. Reagent：Qwen3-8B + 六工具 agent

论文：Exploring Reasoning Reward Model for Agents / Reagent  
链接：https://arxiv.org/pdf/2601.22154

Reagent 是最贴近本项目的公开参照。它直接用 `Qwen3-8B` 跑 GAIA，并把 agent 配成六个固定工具：

| 工具 | 论文描述 |
| --- | --- |
| `Search` | Bing search engine。 |
| `Web Browse` | 输入 URL 和 query，抓网页内容并基于页面回答 query。 |
| `Python Code Interpreter` | 执行 Python code snippet 并返回结果。 |
| `File Reader` | 读取并抽取文件文本内容。 |
| `Image Descriptor` | 给图像和 query，返回视觉问答文本。 |
| `Audio Converter` | 把音频转写成文本。 |

Reagent 的工具实现也明显强于本项目当前免费栈：

| Reagent 公开实现 | 本项目当前 direct run |
| --- | --- |
| Search: Bing Search API。 | `duckduckgo_search/DDGS`，失败时 fallback 到 DuckDuckGo HTML。 |
| Browse: Jina Reader 抓取网页，再用 DeepSeek-Chat 总结。 | `requests.get` + `BeautifulSoup` / `trafilatura`，默认截断文本。 |
| Image2text: GPT-4.1。 | 本地 OCR / image QA 工具。 |
| Audio2text: Whisper-large-v3。 | 本地 audio_transcribe。 |
| Evaluation: max 30 tool-use steps，max response length 32768。 | 本地 direct run 由当前 executor max steps 和本地 vLLM timeout 控制。 |

Reagent 分数口径：

| 模型 / 方法 | 口径 | L1 | L2 | L3 | Overall |
| --- | --- | ---: | ---: | ---: | ---: |
| `Qwen3-8B` base agent | `GAIA(text)` 103 题 | `28.2` | `21.2` | `0.0` | `21.4` |
| `Qwen3-8B` base agent | `GAIA(full)` 165 题 | - | - | - | `20.0` |
| `Reagent-U` | `GAIA(text)` | `59.0` | `38.5` | `16.7` | `43.7` |
| `Reagent-U` | `GAIA(full)` | - | - | - | `38.8` |

注意：`GAIA(text)` 是 text subset，和 test split 无关。它是 103 道偏文本/网页导航的信息检索题。`GAIA(full)` 是 165 道 full validation，包含搜索、多模态、Python、文件推理等。

对本项目的含义：

- Reagent 支持我们把当前 direct executor 写成 `Qwen3-8B fixed-tool GAIA agent baseline`。
- Reagent 的 `20.0` full-GAIA baseline 和我们 `13/81 = 16.0%` 同量级，但它工具后端更强、步数预算更大。

补充：2026-04-28 做了一次 `TOOL-GAIA-V3` 六工具复刻小跑。V3 把 executor 可见工具压成 `search`、`browse`、`python`、`file_reader`、`image2text`、`audio2text`，但中间服务基本都用本项目现有免费/本地能力平替：

| Reagent 工具后端 | 本项目 `TOOL-GAIA-V3` 平替 |
| --- | --- |
| Serper / Bing Search API | `search` 包装当前 `web_search`，实际走 `duckduckgo_search/DDGS` 与 DuckDuckGo 免费栈。 |
| Jina Reader + DeepSeek/OpenAI/Gemini 页面总结 | `browse` 用 `requests` 读取 URL，HTML 走 `html_extract`，网页 PDF 自动下载后走 `extract_pdf_text`，暂未接 LLM 页面总结。 |
| GPT-4.1 image descriptor | `image2text` 包装现有 `image_metadata + ocr_image + image_qa`。 |
| Whisper-large-v3 / 远端 Whisper 服务 | `audio2text` 包装现有 `audio_transcribe`。 |
| Reagent File Reader | `file_reader` 按文件后缀分派到现有 `list_dir/read_file/read_json_file/extract_pdf_text/read_table/parse_docx/parse_pptx/extract_archive/html_extract`。 |
| Python Code Interpreter | `python` 包装现有 `run_python`。 |

这次 no-skill direct 回归使用 `Qwen3-8B-local + validation_test82 + c20`，完成 `81/82`，正确 `9/81`，全集口径 `9/82`。它低于此前 `TOOL-GAIA-V2` 十六原子工具 direct 的 `13/81`。这说明六工具标签可以复刻，但 Reagent 的分数很依赖厚工具实现和较强服务；当 `Search/Browse/Image/Audio` 都换成免费或本地平替后，检索失败、网页抽取弱、视觉/音频质量和参数格式漂移会抵消工具路由简化收益。当前决策是主线回到 `TOOL-GAIA-V2`；`TOOL-GAIA-V3` 挂为 parked candidate，等 `search/browse` 后端增强后再重跑。

### 2. ToolSelf：Vanilla Agent 明确定义为 standard ReAct-style agent

论文：ToolSelf: Unifying Task Execution and Self-Reconfiguration via Tool-Driven Intrinsic Adaptation  
链接：https://arxiv.org/pdf/2602.07883

ToolSelf 明确把 `Vanilla Agent` 定义为 standard ReAct-style agent，等价于没有 `Treconfig` 的基础 agent。它在正文里把 ReAct-style single-agent 形式化为：

```text
history = thought, action, observation
static configuration = strategy, toolbox, knowledge
```

ToolSelf 的 GAIA 相关结果：

| 条件 | 模型 | GAIA 口径 | Acc | 备注 |
| --- | --- | --- | ---: | --- |
| `Vanilla Agent` | `Qwen3-8B` | GAIA main table | `19.7` | standard ReAct-style agent。 |
| `Vanilla Agent` | `Qwen3-8B` | Appendix passive execution | `18.8` | 平均 `7.96` steps。 |
| `TOOLSELF` | `Qwen3-8B` | Appendix | `27.9` | 平均 `32.8` steps。 |
| `TOOLSELF+RFT+KTO` | `Qwen3-8B` | Appendix | `37.6` | 训练后。 |

补充观察：ToolSelf 的 `Vanilla Agent` 可以支撑“Qwen3-8B 作为 ReAct-style GAIA baseline”这一点，但它的工具环境也有明显服务工程加成，不能按“8B + 朴素免费工具”来理解。论文附录里的工具栈更接近一个厚工具环境：

| ToolSelf 工具 | 公开描述里的关键实现 | 对本项目对比的含义 |
| --- | --- | --- |
| `search` | 批量搜索；FRAMES 使用下载版 Wikipedia + BM25，其它任务使用 SearxNG。 | 和本项目 `DDGS` 免费搜索同属搜索工具，但后端、返回结构和稳定性不同。 |
| `visit` | 访问网页；使用 Jina Reader API，并通过 LLM 抽取和压缩与目标相关的信息。 | 更接近 Reagent 的 `Browse = reader + summarizer`，强于原始 `requests + BeautifulSoup` 截断。 |
| `code interpreter` | 隔离 Jupyter kernel，变量可跨步保留，常用 Python 科学计算库可用。 | 和本项目 `run_python` 方向一致，交互态和环境持久性可能更强。 |
| `execute bash` / `str replace editor` | 提供 shell 执行和 SWE-Agent 风格文件编辑。 | GAIA 中未必每题用到，但会增强复杂文件/脚本任务处理能力。 |
| `file analyzer` | 解析 PDF、Word、Excel、PPT、TXT、Markdown；再用 LLM 做目标导向抽取；图片走 `Qwen3-VL-30B-A3B-Instruct`。 | 对 diverse filetype 和多模态题有强工具优势，和本项目原子文件工具、OCR/image QA 存在质量差。 |

因此，ToolSelf `Vanilla Agent 18.8/19.7` 更准确解读为：`Qwen3-8B policy + standard ReAct loop + 厚工具环境 + 约 8 步平均探索`。它对本项目最有用的证据是 baseline 形态对齐；分数差距仍要把 `search/visit/file analyzer/VLM/judge/step budget` 作为控制变量说明。

ToolSelf 还把 GAIA 题型拆成 web browsing、coding、multi-modality、diverse filetype，并展示不同题型下 visit/search/code/file analyzer 等工具选择概率。这说明它把 GAIA 看成多跳工具使用问题，baseline 是同一小模型的受控工具循环。

对本项目的含义：

- 当前 `13/81` 的 executor 形态和 ToolSelf `Vanilla Agent` 是同一类。
- ToolSelf 的增益来自自重配置、更多步数、训练和更厚的工具环境；它的对照对象是 ReAct-style vanilla agent。
- ToolSelf `Vanilla Agent 18.8` 平均约 8 步。本项目很多 web 错题在 1-4 步就提前回答，说明搜索/浏览失败后的继续探索能力更弱。

### 3. ARPO：Qwen3-8B 的 ReAct baseline 和 tool-use RL

论文：Agentic Reinforced Policy Optimization，ICLR 2026  
链接：https://openreview.net/pdf?id=TX4k7BF6aO

ARPO 研究的是 multi-turn LLM-based agents。论文的 agentic tool design 使用三个代表工具：

| 工具 | 作用 |
| --- | --- |
| Search Engine | 执行 web query，返回相关信息。 |
| Web Browser Agent | 访问 search 返回的网页链接，抽取和总结关键内容。 |
| Code Interpreter | 执行模型生成代码并返回结果。 |

ARPO 在 deep search 表里给了 `Qwen3-8B` 的多种 baseline：

| 方法 | 模型 | GAIA overall |
| --- | --- | ---: |
| `Vanilla RAG` | `Qwen3-8B` | `20.4` |
| `Search-o1` | `Qwen3-8B` | `21.4` |
| `WebThinker` | `Qwen3-8B` | `22.3` |
| `ReAct` | `Qwen3-8B` | `23.3` |
| `Qwen3-8B + ARPO` | `Qwen3-8B` | `38.8` |

ARPO 还特别指出，search feedback 比 Python feedback 带来更高不确定性；这和本项目错题里的搜索结果不稳、snippet 不足、网页抓取失败高度一致。

对本项目的含义：

- 对 GAIA deep search，`Qwen3-8B ReAct` 是公开标准 baseline。
- 本项目 direct executor 是可接受的 baseline 范式。
- 分数差异要优先看 search/browser 后端、最大步数、工具调用格式、训练数据和 judge；ReAct 形态本身已有公开 baseline 支撑。

### 4. Search-R1：多跳搜索题的小模型组织方式

论文：Search-R1: Training LLMs to Reason and Leverage Search Engines with Reinforcement Learning  
链接：https://arxiv.org/pdf/2503.09516

Search-R1 属于多跳搜索强化学习论文，范围小于 full GAIA，但它非常适合支撑“多跳人物/事实题”的小模型组织方式。它让模型在推理中显式触发搜索：

```text
<think>...</think>
<search>query</search>
<information>retrieved content</information>
<think>...</think>
<answer>...</answer>
```

它的模型包括 `Qwen2.5-7B` 和 `Qwen2.5-3B`。这说明 3B/7B 级小模型也常被训练成“边思考边调用搜索环境”的 agent policy，超出单轮 answer-only prompt。

对本项目的含义：

- 多跳人物题的标准小模型基线可以是 interleaved reasoning + search。
- 本项目当前 `web_search -> observation -> continue` 正是这个范式的 GAIA 扩展版。

## Skill 论文 baseline 矩阵

旧版两份文档里真正需要保留的是这一层口径：skill 方法的主表通常围绕同一 executor / harness 下的 skill 有无展开；强模型 direct 只做 reference。

| 条件 | 公开论文里的常见名字 | 本项目对应 | 用途 |
| --- | --- | --- | --- |
| strong reference | GPT-4 / GPT-5 / Claude direct，GAIA official assistant baseline。 | `GPT-5.2 no-skill direct = 32/81`。 | 给强模型上限或系统 reference，不作为 8B skill 主对照。 |
| vanilla weak agent | `Vanilla Agent`、`No Pipeline`、fixed-action agent、baseline agent。 | `Qwen3-8B no-skill direct = 13/81`，当前主线为 `TOOL-GAIA-V2 / atomic_v2`。 | 8B 弱模型基础能力；这是主 baseline。 |
| same-harness empty control | `No Skills`、`skill-path none`、`w/o Skill Library`、empty skill library。 | 只有当 with-skill 引入额外 phase graph / skill-aware prompt / loading mechanism 时，再补 neutral empty-library 条件。 | 隔离 harness 形式收益和真实 skill 内容收益。 |
| treatment | with skills、workflow memory、programmatic skill、skill library、reconfiguration。 | bootstrap skill、iterated skill、后续 progressive disclosure / skill pool。 | 报告 skill 内容带来的增益。 |

当前短期主表建议：

| 记录名 | 工具 / executor | skill 条件 | 口径 |
| --- | --- | --- | --- |
| `8B_no_skill_react_v2` | `Qwen3-8B-local + TOOL-GAIA-V2 + fixed ReAct protocol` | 无 skill。 | 主 weak-model baseline。 |
| `8B_bootstrap_skill_v2` | 同一 executor / toolbox / scorer。 | bootstrap skill。 | 初始 skill 增益。 |
| `8B_iter_skill_v2` | 同一 executor / toolbox / scorer。 | iterated / actor-refined skill。 | SkillRL / 迭代收益。 |
| `5.2_no_skill_reference` | GPT-5.2 direct。 | 无 skill。 | strong-model reference。 |

若 with-skill run 的 prompt 或 phase logging 和 direct run 差异过大，再补一个技术控制项：

| 控制项 | 设置 | 解释 |
| --- | --- | --- |
| `same_harness_neutral_empty` | 走 skill-aware executor / phase logging，但 phase 文本只保留中性流程占位，不写 GAIA 经验规则。 | 测 harness 形式收益。 |
| `default_phase_scaffold` | 允许当前默认 INIT/GATHER/ANALYZE/CONCLUDE scaffold 生效。 | 测手写轻量 workflow scaffold 的收益。 |

这个控制项服务于严谨性；当前主问题仍是 `8B_no_skill_react_v2` 作为 vanilla fixed-tool GAIA agent 是否合理。Reagent、ToolSelf、DynaSaur、ARPO 都支持这种受控工具 agent 口径。

## 其他 Skill 论文的可用边界

### SkillsBench / SkillLearnBench

这两类工作支持一个简单工程原则：同一 solver / harness 下，只改变 skill path 或 skills directory。`No Skills` 或 `skill-path none` 就是 no-skill baseline；with-skill 条件加载 curated、human-authored 或 generated skill。

对本项目的映射是：同一 `Qwen3-8B-local + GAIA scorer + TOOL-GAIA-V2` 下比较 no skill / bootstrap skill / iterated skill。若后续改成 progressive disclosure，也要保留同一 executor 里的 no-skill 或 empty-library 条件。

### Agent Skill Framework for SLMs

这篇工作适合作为“小模型 skill routing 需要单独测”的证据，但它没有提供 GAIA 式多模态、多工具自由题 executor。它的实验集中在 IMDB、FiNER、InsurBench 等文本任务，核心条件是：

| 方法 | 含义 | 对本项目的启发 |
| --- | --- | --- |
| `DI` | Direct Instruction，最小 prompt 原始输入。 | 抽象上对应 no-skill direct，但它是单轮文本任务。 |
| `FSI` | Full-Skill Instruction，一次性给完整临时 skill repo。 | 对应一次性注入完整 skill。 |
| `ASI` | Agent Skill Instruction，模型先选择 skill，再披露对应 skill。 | 对应 progressive disclosure / on-demand load。 |

它对本项目最有用的点是指标设计：8B 在多 skill 或复杂 phase 下可能卡在选择/加载。建议记录 `skill_candidate_count`、`skill_selected`、`skill_loaded_step`、`skill_context_bytes`、`skill_selection_error`、`phase_or_skill_used_in_final_answer`。

### DynaSaur / ASI / AWM / SkillWeaver / SAGE

这些工作共同支持“固定动作 baseline + skill/action/library treatment”的组织方式：

| 工作 | baseline 层 | skill / treatment 层 | 对本项目的含义 |
| --- | --- | --- | --- |
| DynaSaur | raw LLM、Sibyl / HF Agent fixed-action agent。 | 动态生成 Python action，并复用 action library。 | GAIA 上 raw、fixed-action、dynamic-action 可以分层；本项目 direct executor 属于 fixed-action 层。 |
| ASI / AWM | BrowserGym / WebArena primitive browser actions。 | textual workflow memory 或 programmatic skill 加入 action space。 | web skill 论文保留原始 web agent baseline。 |
| SkillWeaver | CodeAct-style web agent，只用 atomic browsing actions。 | Playwright API skill library。 | 强模型产 skill、弱模型消费 skill时，baseline 仍是同一弱模型 atomic-action agent。 |
| SAGE | vanilla / SFT / GRPO without skill library。 | skill library + skill-integrated reward。 | 若后续训练 executor，需要同训练流程下的 without-skill-library 对照。 |

因此，当前对外写法可以统一成：

> Our downstream GAIA environment is a controlled fixed-tool executor. The no-skill condition evaluates Qwen3-8B under the same toolbox, action protocol, observation loop, and scorer used by skill conditions. Skill conditions add only generated or iteratively improved skill content. Strong-model no-skill results are reported as references.

## 本项目 direct executor 对齐点

当前本项目 direct executor 的形态：

| 维度 | 本项目 |
| --- | --- |
| 模型 | `Qwen3-8B-local`。 |
| 执行器 | `DirectEnvironment` + `DirectExecutorAgent`。 |
| 协议 | `<THOUGHT>` + `<CALL>/<ARGS>` 或 `<ANSWER>`。 |
| 工具 | `web_search`、`fetch_url`、`html_extract`、`run_python`、`read_file/read_json_file/read_table`、OCR、image QA、audio transcription、PDF/text extraction 等。 |
| 反馈 | tool observation 追加回 history。 |
| 打分 | GAIA official-style final answer match。 |
| no-skill | system prompt 明确 “No skill is activated”。 |

和公开论文的对应：

| 公开论文 | 对应关系 |
| --- | --- |
| Reagent `Qwen3-8B` base agent | 同为 fixed tool suite + tool call/response loop。 |
| ToolSelf `Vanilla Agent` | 同为 standard ReAct-style passive executor。 |
| ARPO `Qwen3-8B ReAct` | 同为 search/browser/code tool-use agent。 |
| Search-R1 | 同为 interleaved reasoning + retrieval environment，工具集合更窄。 |

因此本项目可以自信写：

> We evaluate Qwen3-8B as a controlled fixed-tool GAIA agent, following the common small-model GAIA setup used by Reagent, ToolSelf, and ARPO.

### 工具后端差异

| 能力 | 公开强 baseline 常见实现 | 本项目当前实现 | 风险 |
| --- | --- | --- | --- |
| Search | Bing Search API / search API。 | `duckduckgo_search/DDGS` 免费层级，失败 fallback 到 DuckDuckGo HTML。 | 结果少、空结果、snippet 过时、反爬和地域差异。 |
| Browse | Jina Reader + LLM summarizer；或专门 browser agent。 | `requests.get` + HTML text extraction；`fetch_url` 对 PDF 只返回 raw bytes。 | 动态页、PDF、Wayback、Wikipedia history、data portal 处理弱。 |
| Image | GPT-4.1 / strong VLM。 | 本地 OCR / image QA。 | 图表、照片、细节推断弱。 |
| Audio | Whisper-large-v3。 | 本地 audio_transcribe。 | 质量看本地模型和参数。 |
| Step budget | Reagent eval max 30 tool-use steps；ToolSelf 可 30+ steps。 | direct run 多数题 1-5 步，且本地 vLLM streaming timeout 会影响长尾。 | 复杂题探索不足。 |

## 错题证据

### 1. data.census.gov 官方数据题：搜索只能拿到泛化页面

task：

```text
d1af70ea-a9a4-421a-b9cc-94b5e02f1788
```

问题：Washington state county seats，要求 2020 census official data from data.census.gov。  
gold：`736455`  
本地答案：`Data not accessible with available tools`

轨迹：

- `web_search("2020 census Washington state county seats population by land area")` 返回 Census story page、Washington OFM data page、citypopulation.de。
- `web_search("2020 census Washington state county seats population land area data.census.gov")` 仍返回 Census story page 和 OFM page。
- executor summary 写明 search results 没有直接提供所需 dataset/table。

这类题需要稳定的官方数据检索、站内查表、可能还要 Census API / data.census.gov 深链。DDGS snippet 很难直接给到答案。

### 2. YouTube / 视频画面题：搜索返回空结果

task：

```text
20194330-9976-4043-8632-f8485c6c71b2
```

问题：Game Grumps Sonic 2006 第一集 30 秒处红底白字短语里字母 E 出现几次。  
gold：`4`  
本地答案：`Unable to determine`

轨迹：

- `web_search("Game Grumps Sonic the Hedgehog 2006 Let's Play 30 second phrase", max_results=1)` 返回 `[]`。
- executor 直接判断当前工具无法确定。

这说明免费 search 对长尾视频细节查询非常不稳。更强系统可能会搜到 YouTube、transcript、wiki/fandom、甚至需要视频/截图工具。

### 3. Wikipedia revision / image history 题：搜索空结果 + 普通 fetch 不会查历史

task：

```text
d5141ca5-e7a0-469f-bf3e-e773507c86e2
```

问题：Principle of double effect 页面里 St. Thomas Aquinas 图片首次加入日期。  
gold：`19/02/2009`  
本地答案：`Unable to determine`

轨迹：

- 三次 `web_search` 都返回 `[]`。
- `fetch_url("https://en.wikipedia.org/wiki/Principle_of_Double_Effect")` 只抓当前页面文本。
- executor summary 写明当前 Wikipedia page content 没有 image upload date。

这类题需要 Wikipedia revision API / page history diff / image file usage 轨迹。普通 search + 当前页面 fetch 无法覆盖。

### 4. PDF 官方统计题：fetch_url 抓到 raw PDF bytes

task：

```text
e0c10771-d627-4fd7-9694-05348e54ee36
```

问题：2011 Bulgarian census tertiary education gender split。  
gold：`234.9`  
本地答案：`Insufficient data`

轨迹：

- `web_search` 找到 `2011 POPULATION CENSUS Main Results - nsi.bg` PDF。
- `fetch_url` 抓到 `content_type: application/pdf`，text 以 `%PDF-1.5` 开头。
- executor summary 写明 fetched PDF content is binary。

这里的来源已经被找到，瓶颈落在浏览工具对 PDF 的默认处理。虽然本项目有 `extract_pdf_text` 工具，但 executor 在这个题里没有切换过去。Reagent 这类系统的 Browse 由 Jina Reader + LLM summarizer 支撑，PDF/网页抽取链路更强。

### 5. Wayback / archived citation 题：archive URL 404 后直接猜

task：

```text
0e9e85b8-52b9-4de4-b402-5f635ab9631f
```

问题：Carl Nebel Wikipedia 第一条 citation link 的页面图片里最新年份。  
gold：`1927`  
本地答案：`1855`

轨迹：

- `fetch_url("https://en.wikipedia.org/wiki/Carl_Nebel")` 成功。
- `fetch_url("https://web.archive.org/web/20091118000000/http://www.dorothy-sloan.com/...")` 返回 404。
- executor 改为根据 Wikipedia text 猜 `1855`。

这类题需要更鲁棒的 Wayback URL 查询、snapshot 选择、网页图片 OCR。当前 raw fetch 碰到 404 后缺少恢复策略。

### 6. 时间敏感 roster 题：snippet 用了当前 active players，和题目时间不一致

task：

```text
a0c07678-e491-4bbc-8f0b-07405144218f
```

问题：Taishō Tamai 2023 年 7 月相邻号码的 pitchers。  
gold：`Yoshida, Uehara`  
本地答案：`Yamasaki, Uehara`

轨迹：

- `web_search("Taishō Tamai jersey number 2023 adjacent pitchers")` 返回 NPB active players snippet：
  - 18 Pitcher Yamasaki
  - 19 Tamai
  - 20 Uehara
- 模型直接信了 snippet。

错误点是 temporal mismatch：题目要求 as of July 2023，search snippet 给的是当前或非指定时间 roster。更强浏览/搜索流程应该打开页面、找历史 roster 或时间版本。

## 对 13/81 的解释边界

可以说：

- 当前范式与公开小模型 GAIA baseline 对齐：fixed-tool ReAct agent。
- 分数低于公开 `18-23` 的 vanilla agent baseline，有直接证据指向工具后端差异，尤其是 search/browse。
- 本地 run 的 web-related 正确率 `10.9%` 明显低于 non-web `22.9%`。
- 错题里存在搜索空结果、snippet 过时、PDF raw bytes、Wayback 失败、未继续 browse/history/API 的具体轨迹。

需要避免过度断言：

- `13/81` 不能全部归因到 DDGS。还有模型能力、步数预算、prompt、tool selection、local vLLM streaming timeout、多模态工具质量等变量。
- 公开论文分数常来自不同 split、不同工具、不同 judge 和训练后模型。Reagent full `20.0` 是 165 题，ToolSelf / ARPO 可能使用筛选子集或自定义 deep search split，需要在论文里明确口径。
- 本项目 test82 是本地切片，和 GAIA public validation 165 题不能直接逐点比较。
