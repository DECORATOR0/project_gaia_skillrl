## 预期调度顺序

master 同时保留两条版本队列：

1. 已启动 direct baseline、ARCH-V4、ARCH-V5 strict。
2. 当 ARCH-V4 或 ARCH-V5 strict 任一版本队列退出后，master 自动补 `ARCH-V5.1 any_phase`。
3. 再有版本队列退出后，master 自动补 `ARCH-V5.2 no-CONCLUDE`。

每个版本队列内部：

1. boot_dev 先跑。
2. boot skill 生成后启动 boot_test。
3. boot_dev state 达到 tail threshold 后，启动 A/B offline strong-model 生成。
4. A/B skill 生成后启动 A_dev/A_test/B_dev/B_test。

## 异常处理

如果 master PID `838871` 已退出：

1. 先看状态文件里的 `Failures`。
2. 再看 master log。
3. 查子进程是否还在跑，避免重复启动同一 prefix。

```bash
ps -eo pid,ppid,pgid,sid,stat,etime,cmd | rg '20260503_0113|run_gaia_qwen35_9b_remote_master_queue|run_gaia_archv5|run_gaia_fresh'
```

如果远端 API 不通：

```bash
ss -ltnp 2>/dev/null | grep 18000 || netstat -ltnp 2>/dev/null | grep 18000
curl -sS --max-time 8 http://127.0.0.1:18000/v1/models
```

大概率需要恢复 Windows 侧 SSH 反向隧道：

```powershell
ssh -N -o ExitOnForwardFailure=yes -R 127.0.0.1:18000:172.16.1.101:8000 254
```

如果某个子 run 失败：

- 优先保留现有 run 目录和日志。
- 只补失败的具体版本或具体阶段。
- 补跑前先确认同名 prefix 下没有活跃进程。
