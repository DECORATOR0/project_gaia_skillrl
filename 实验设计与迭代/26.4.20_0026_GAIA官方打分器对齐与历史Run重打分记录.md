# 26.4.20_0026_GAIA官方打分器对齐与历史Run重打分记录

## 1. 背景

2026-04-20 对 `project_gaia_skillrl` 的 GAIA 判分链路做了一次重要修正，目标是把本地分数和官方 leaderboard 的口径对齐。

修正前，本地判分逻辑偏粗，核心特点只有两点：

- 做少量字符串归一化
- 归一化后直接做字符串相等比较

这套逻辑会把一批官方应判对的答案记成错，例如：

- `132,133,134,197,245` 对 `132, 133, 134, 197, 245`
- `42` 对 `42.0`
- `sea gull` 对 `seagull`

这类误差会直接影响训练复盘、基线对比和后续分数判断，所以需要单独记录。

## 2. 官方口径

官方参考源有两处：

- leaderboard 入口：<https://huggingface.co/spaces/gaia-benchmark/leaderboard/blob/main/app.py>
- scorer 实现：<https://huggingface.co/spaces/gaia-benchmark/leaderboard/blob/main/scorer.py>

官方 scorer 的关键行为可以概括成三类：

- 数字题：去掉 `$`、`%`、`,` 再转成数值比较
- 列表题：如果 gold 含 `,` 或 `;`，按列表拆开逐项比较
- 字符串题：去掉空白并转小写；普通字符串比较默认也会去标点

这个口径决定了 GAIA 更接近“归一化后的 exact match”，不是原始字符串逐字符相等。

## 5. 重要说明

### 5.1 `train2` 会对应三份分数

训练配置是两轮 actor-critic 训练，然后再跑一次最终验证。

代码位置在 [trainer.py](/data/xsy/project_gaia_skillrl/gaia_skillrl/trainer.py:346) 到 [trainer.py](/data/xsy/project_gaia_skillrl/gaia_skillrl/trainer.py:368)：

- `iteration_01`：第 1 轮训练内评估
- `iteration_02`：第 2 轮训练内评估
- `run_summary.json`：两轮结束后的最终验证

因此 `c20`、`c20G` 这类 run 会同时存在“两轮训练分”和“最终验证分”。

### 5.2 `c20` 是并发标签，不是分数标签

在 [config_snapshot.json](/data/xsy/project_gaia_skillrl/runs/2026/4/2026-4-18/20260418_130731_gaia_validation53_level1_train2_qwen3_8b_gpt54_c20/config_snapshot.json:50) 里可以看到：

- `iterations_per_batch = 2`
- `task_concurrency = 20`

所以 `train2` 对应两轮训练，`c20` 对应并发 20。`c20G` 里的 `G` 是人工附加的变体标签。

### 5.3 后续分数对比统一按官方口径

从这次修正开始，后续几类工作都建议统一用官方 scorer：

- direct baseline 对比
- 训练前后对比
- 历史 run 复盘
- 文档里的正式分数

旧口径分数仍然可以保留在原始产物里，用来追溯历史。正式比较时应优先引用 `official_gaia_rescore.json`。

## 6. 后续建议
