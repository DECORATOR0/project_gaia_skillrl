## 机制结论

### 1. 答案协议从 `CONCLUDE-only` 走向 `any_phase / no-CONCLUDE`

早期图里只有 `CONCLUDE` 能答，导致 `invalid_answer_phase`、`REPAIR -> CONCLUDE` 非法跳转、空答和提前答摩擦。ARCH-V4 增强反馈后，空答下降但 invalid action 仍高。V5.1 `any_phase` 和 V5.2 `no-CONCLUDE` 明显压低 invalid/empty，但也让“何时该提交答案”变成新问题。

当前方向应是：保留 no-CONCLUDE / any_phase，同时增加显式 `answer_now`、低步数收口、候选缓存和重复工具调用熔断。

### 2. 搜索后端是 GAIA 分数解释的第一层过滤器

DDG / DDGS 免费栈能做 smoke，但 timeout/403 会成片污染分数。4 月 29 日 V5.2 r2 的低分主要来自 boot 段搜索全 timeout。Serper 和 Brave 把 `web_search` 外部失败压低后，协议和 skill 差异才更可解释。

后续所有 GAIA/Search 实验应先记录 search smoke、provider、proxy、key 顺序、fallback 和 search error type。

### 3. 9B 比 8B 更强，也更容易长链和过度取证

9B direct / skill 能把 test 提到 30 分以上，旧 best `39/82` 也来自 9B。代价是长 reasoning、hit max-step、forced answer、HTTP400/context、streaming empty 和 token/KV 压力。token guard 修了 HTTP400，但没有修“模型在最后几步仍继续搜索和修复”的策略问题。

后续 9B 要把预算、答案收口和工具重试一起控，不宜单纯加步数。

### 4. 更优雅的图未必更适合当前 executor

ARCH5.3 把 phase 名称和职责拆得更清楚，也收窄 allowlist；结果 B1/B2 test 低于旧 ARCH5.2 B。对 9B 来说，过窄 allowlist 和额外 phase hop 会增加 forced answer，尤其是 PDF/table/image/media/repair 相关任务。

下一版如果继续 B3，应恢复旧 B 的关键能力：宽一点的 VERIFY/REPAIR 工具面、prompt-only 快路径、WEB 一主一备硬预算、LOCAL parser fallback。

### 5. GAIA 已经暴露了方法问题，下一步需要更干净的验证场

GAIA 帮忙找到了真实问题：搜索波动、工具失败、答案协议、状态图摩擦、预算、forced answer、cross-model 稳定性。它也把太多因素混在一起，继续刷 GAIA 分数的边际收益变低。迁到 SkillsBench / SkillFlow / SkillLearnBench / OfficeQA / SealQA / SQLBench 等更可控 benchmark，可以更快判断“skill 工件 + critic/actor 修改”本身是否有效。

## 后续建议

1. GAIA 侧保留旧 best 复跑和 B3 小改，不再大规模堆新图。B3 只改最关键的 VERIFY/REPAIR 工具面、prompt-only 快路径、WEB budget 和 answer_now。
2. 9B GAIA 复跑固定采用 token guard + Serper 有余额 key + `17890` 代理 smoke + forced answer 统计，避免再把网络和预算漂移混入架构判断。
3. 新 benchmark 侧优先跑两个最小闭环：
   - SkillsBench native smoke，前提是 Docker/BenchFlow 权限解决。
   - OfficeQA `evoskill_corpus` 或 SealQA/SQLBench 的 baseline vs skill 小实验，用现有可评分资产先验证 critic/actor 是否能带来稳定收益。
4. B2/SkillFlow 方向把 actor 输出改成 patch schema：`op / target / evidence / expected_metric_effect / rollback_condition`，避免 actor 写出泛化建议后没有结构变化。
5. 每次新 benchmark 不直接套 GAIA 七阶段。先按 benchmark 原生 workflow 写 domain-specific phase，再决定是否需要状态图和 allowlist。
