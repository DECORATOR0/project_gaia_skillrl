## A_full critic 的判断

critic 的核心判断：

> The locked graph is adequate; the main loss is instruction quality, not topology.

它归纳的主要失误是四类：

1. `WEB_EVIDENCE` 从 paraphrase、current page、wrong variant 回答，没有对齐指定 source slice / 日期 / 版本。
2. `WEB_EVIDENCE` 对 counting、intersection、fixed-denominator 任务持续搜索到 max-step，没有及时冻结集合并交给 `COMPUTE`。
3. `LOCAL_EVIDENCE` 对 structured binary / media clues 处理太松，把 PDB/XLSX/ZIP/XML/audio/image 当成 loose text 或持续错误 reader。
4. `COMPUTE` / `VERIFY` 让 plausible-but-wrong 的 scope、literal wording、formula/rounding 假设通过。

critic 给出的 protected behaviors：

- 保留 `INIT` 的 cheap routing 和少数 prompt-only direct answer。
- 保留 `LOCAL_EVIDENCE` 在附件直接决定答案时的 direct answer。
- 保留 `WEB_EVIDENCE` 对简单 authoritative lookup 的 fast path。
- 保留 `WEB_EVIDENCE -> COMPUTE -> VERIFY` 的 clean numeric path。

这点很重要：A_full 不是把 skill 全面重写成保守版本，而是在保护 fast path 的前提下加了若干 source/scope/structured parsing 约束。

> Tightened exact-source and fixed-set handling in WEB_EVIDENCE, made LOCAL_EVIDENCE switch earlier to structured parsing, and added scope/wording/rounding checks in COMPUTE, VERIFY, and REPAIR.

### Common Base Info

新增/强化了四类全局规则：

- 工具调用因 phase scope 或 required args 失败时，不重复同一个坏调用；修正一次或先转 phase。
- quote / archive / revision / page-specific / date-sensitive 任务必须来自匹配 source slice，不接受 paraphrase、summary、present-day variant。
- decisive fact ambiguous / contradictory / secondary wording variant 时进 `REPAIR`。
- 本地证据给出的 identifiers、rows、timestamps、transcript lines、OCR tokens、candidate names 后续要原样携带，避免 loose rediscovery。

框架含义：这不是题目专属修补，而是给 executor 增加“证据字符串保真”和“失败调用去循环”的全局归纳偏好。

### INIT

变化较小：

- `historical revisions` 改成更宽的 `revision history`。
- final-format 锁定中加入 `quote fidelity`。
- 直接回答的描述略收紧，减少“trivial text transformation”式泛化。

框架含义：INIT 仍负责早路由，不把复杂校验提前塞进 INIT。

### LOCAL_EVIDENCE

主要新增：

- 对 `PDB, XLSX, ZIP, XML` 等 binary/structured files，format-native reader 失败一次后立刻切 `run_python` 或 `extract_archive`。
- 明确不要对 binary content 循环 `read_file`。
- audio/image 任务要保存 exact transcript / OCR tokens。
- handoff 给 WEB 时要带 exact identifiers。

框架含义：附件题的核心不是更长说明，而是“reader 失败后快速升级到结构化解析”，这应该迁移进 bootstrap prompt 或 preprocess 字段。

### WEB_EVIDENCE

这是改动最大的 phase。

新增/强化：

- `source slice` 概念：实体、日期、版本、页面、heading、location 都要匹配。
- archive / revision / quote / exact-line 任务，必须 fetched page/capture 自身含 decisive wording。
- current page 不能替代 old state / specific revision。
- fixed denominator / candidate set 完成后停止搜索，交给 `COMPUTE`。
- 同一 source family 连续两次 `403/404/SSL/timeout/schema error` 后，不再 broad search，去 `REPAIR`。
- final answer 只有在 correct source slice 直接支持时才允许。

框架含义：这可能是 A_full 提升的主因。它把“网页任务继续搜”改成了“对齐 source slice + 冻结集合 + 交给 compute/verify/repair”。

### COMPUTE

主要新增：

- pre-compute checklist：candidate set、inclusion rule、units、rounding mode、output shape。
- optimization / intersection / chronology / probability 用 exhaustive 或 cross-checked scripts。
- 保留 literal labels/source wording，避免用 hypernym 或 near-synonym 替代。
- VERIFY 条件新增 row/formula selection、earliest/oldest ordering、exact source wording。

框架含义：COMPUTE 的关键不是写更多 Python，而是把“集合边界和字面标签”作为计算前状态锁定。

### VERIFY

主要新增：

- 每次验证只盯一个最可能翻转答案的 high-risk assumption。
- 重点假设包括 exact wording、date slice、version、group membership、oldest/earliest、row/formula、inclusion boundary。
- 如果 candidate 依赖 synonym、spelling variant、generalized category、present-day page、secondary source，就进 `REPAIR`。

框架含义：VERIFY 从“全面确认”变成“定位一个最危险假设”。这更适合 24-step budget，也减少模型用重复 paraphrase 误认为验证。

### REPAIR

主要新增：

- blocker 增加 `wrong source slice`。
- structured repair 增加 XML/PDB。
- 避免重复同一 search/parse/rejected tool call。
- 如果 repair 产出缺失值但还需 set comparison / chronology / selection logic，去 `COMPUTE`。

框架含义：REPAIR 不是宽泛重启，它是 bounded blocker repair。

## 从框架角度怎么看 A_full

A_full 的结论不是“这个 A skill 手写得更好”，而是：

1. 当前 BOOT-V4 生成的 graph 已经够用，至少 A critic 没要求改图。
2. 性能差异来自固定图内的若干可迁移 instruction biases。
3. 这些 biases 都能被写回框架，而无需手工保存某个 skill：
   - bootstrap 生成时更强调 source-slice exactness。
   - preprocess 时显式产出 route / tool_order / risk_check。
   - critic reward schema 强制归因到 source alignment、handoff timing、structured parsing、verification risk。
   - actor prompt 要求保护 fast path，同时加“失败调用不循环”“集合完成即交给 compute”的规则。

## 可迁移回 BOOT/进化框架的方向

优先级从高到低：

### 1. 结构化 preprocess

当前 preprocess 只有一条 `preprocess_note`。建议改成结构化：

```json
{
  "task_id": "...",
  "likely_route": "WEB_EVIDENCE | LOCAL_EVIDENCE | COMPUTE | MIXED",
  "tool_order": ["read_json_file", "web_search", "fetch_url", "run_python"],
  "source_alignment": "date/revision/page/exact-line requirement",
  "format_pressure": "single token / exact quote / integer / fixed decimals / comma list",
  "risk_check": "one assumption most likely to flip final answer"
}
```

理由：A_full 的成功倾向大量依赖“source slice / fixed set / risk assumption”。这些字段在 preprocess 阶段更容易从题面和 gold answer shape 中提炼出来，再让 bootstrap skill architect 泛化成 phase rules。

### 2. Bootstrap skill prompt 增加 A_full 式硬要求

在 `bootstrap_skill_system.md` / `bootstrap_skill_user.md` 增加几条生成要求：

- WEB phase 必须包含 source-slice alignment：date、version、revision、page、heading、quote、exact-line。
- WEB phase 必须包含 fixed-set stop condition：候选集/denominator 完整后交给 compute。
- LOCAL phase 必须包含 structured-file escalation：PDB/XLSX/ZIP/XML reader 失败一次后切 run_python/extract_archive。
- VERIFY phase 必须是 high-risk assumption check，而非 broad verification。
- REPAIR phase 必须避免重复同一失败调用。

这样可以让 boot 初始 skill 直接带 A_full 倾向，减少后续 actor 才补上的概率。

### 3. Critic prompt schema 加强可迁移归因

当前 critic 已经能输出 node_edits，但可以让 reward schema 更框架化：

```json
{
  "failure_taxonomy_counts": {
    "source_slice_mismatch": 0,
    "web_fixed_set_not_frozen": 0,
    "structured_local_parse_failure": 0,
    "compute_scope_error": 0,
    "verify_wrong_assumption": 0,
    "repair_loop": 0
  },
  "prompt_rule_candidates": [...],
  "protected_fast_paths": [...]
}
```

这样后续不是只生成一次 skill，而是能统计多轮后把高频规则回灌 bootstrap prompt。

### 4. Actor prompt 增加“保护 fast path + 小幅规则增补”

A_full 比较好的地方是没有把 skill 改成过度保守。可以把这变成 actor prompt 的硬偏好：

- 保留已成功的 direct-answer / fast lookup path。
- 修改集中在 failure-heavy phase。
- 每个 phase 只增加能改变行为的规则，避免泛泛安全话术。
- 禁止用大量 generic verification 文案稀释 executor 注意力。

### 5. 把 `qwen3-8b` 历史措辞修掉

`bootstrap_skill_user.md` 和 `actor_system.md` 都有面向 `qwen3-8b` 的历史措辞。当前 executor 是 `Qwen3.5-9B-local`。建议改成 runtime 注入：

```text
Keep instructions concise and operational for the executor model in runtime_contract.executor_model.
```

这不是大改，但能减少版本语义混乱。

## 当前不建议做的事

- 不建议手工直接改 A skill 继续跑，然后把高分当成框架成功。这样无法回答“如何稳定生成这种倾向”。
- 不建议立刻大改 BOOT-V4 graph。A_full 的 critic 证据显示 graph adequate，收益来自固定图内规则。
- 不建议只按 dev failure case 过拟合出题目专属规则。应该提取 source-slice、fixed-set、structured parsing、risk verification 这些跨题型规则。

   - `bootstrap_task_preprocess_*`
