## Skill 两次改写到底带来了什么

### iteration_01 actor 之后

- 参考：[iteration_01 before_actor](/data/xsy/project_gaia_skillrl/runs/2026/4/2026-4-18/20260418_171627_gaia_validation53_level1_train2_qwen3_8b_gpt54_c20G/iteration_01/skill_before_actor/gaia-general-skill/SKILL.md) / [iteration_01 after_actor](/data/xsy/project_gaia_skillrl/runs/2026/4/2026-4-18/20260418_171627_gaia_validation53_level1_train2_qwen3_8b_gpt54_c20G/iteration_01/skill_after_actor/gaia-general-skill/SKILL.md)
- INIT 被显著收窄：只允许 `read_json_file(task.json)` 和 `list_dir(.)`，禁止在 INIT 用提取工具、web 和 `run_python`。
- GATHER 新增“每个相关附件至少做一次 phase-correct 尝试”“web 被 block 时换 accessible alternate source”“不要在 GATHER 用 `run_python`”“不要太早 conclude unable to determine”。
- ANALYZE 强化了“对自包含 arithmetic / logic / counting / string 问题优先用 `run_python`”“source-based 问题要提 exact wording”“count/list 题要做边界和去重检查”。
- 这一轮 skill 的核心目标是：先把 phase 纪律和早退行为压住，再补一点 exact wording。

### iteration_02 actor 之后

- 参考：[iteration_02 before_actor](/data/xsy/project_gaia_skillrl/runs/2026/4/2026-4-18/20260418_171627_gaia_validation53_level1_train2_qwen3_8b_gpt54_c20G/iteration_02/skill_before_actor/gaia-general-skill/SKILL.md) / [iteration_02 after_actor](/data/xsy/project_gaia_skillrl/runs/2026/4/2026-4-18/20260418_171627_gaia_validation53_level1_train2_qwen3_8b_gpt54_c20G/iteration_02/skill_after_actor/gaia-general-skill/SKILL.md)
- INIT 新增“先区分 exact extraction 和 derived answer”“如果是自包含 reasoning，提前计划在 ANALYZE 用 `run_python` 做 exhaustive verification”。
- GATHER 新增本地附件的 path / format fallback，要求保留 qualifier。
- ANALYZE 进一步加强：把 `minimax`、`grid/letter search`、`string manipulation`、`edge cases`、`spelling quirks`、`preserve specificity` 都明确写进约束。
- 这一轮 skill 的核心目标是：把“精确抽取”和“可穷举的自包含推理”都压实。

## 为什么 skill 没把自动机真正压实

1. phase graph 和 tool allowlist 是 runtime 硬编码的，skill 只能改自然语言说明，改不了执行机制本身。参考 [_build_phase_transition_graph](/data/xsy/project_gaia_skillrl/gaia_skillrl/environment.py:74) 和 [_build_phase_tool_allowlist](/data/xsy/project_gaia_skillrl/gaia_skillrl/environment.py:92)。
2. 违规处理走的是“先输出，再驳回”的路径。executor 先输出 `<ANSWER>` 或非法 `<NEXT>`，runtime 再回 feedback 让它重来。参考 [_phase_runtime_instruction](/data/xsy/project_gaia_skillrl/gaia_skillrl/agent_loop.py:251)、[invalid_answer_phase](/data/xsy/project_gaia_skillrl/gaia_skillrl/agent_loop.py:407)、[invalid_phase_transition](/data/xsy/project_gaia_skillrl/gaia_skillrl/agent_loop.py:514)。
3. `remaining_steps <= 3` 时会自动 fallback conclude。这个机制能防止无穷拖延，但也会制造“最后补手续”的收尾。参考 [fallback conclude](/data/xsy/project_gaia_skillrl/gaia_skillrl/agent_loop.py:347)。
4. 工具覆盖范围本身不够。很多题在 GATHER 阶段就拿不到有效证据，后面的 phase 只能围绕残缺 observation 转。参考 [read_table](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:226)、[image_metadata](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:243)、[fetch_url](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:303)、[run_python](/data/xsy/project_gaia_skillrl/gaia_skillrl/tools.py:324)。
5. `run_python` 只是自然语言建议，不是强制执行。像 [iter2-bob](iteration_02/task_37_e142056d.md) 这种标准 minimax 题，以及 [iter2-commutative](iteration_02/task_21_6f37996b.md) 这种小规模可穷举题，skill 已经明确写了“应当 Python 验证”，executor 依然没有稳定做到。

## 两轮变化怎么看

### 好消息

- 自动机层面确实更完整了：完整 phase path `46 -> 50`，未到 `CONCLUDE` 的失败题 `7 -> 3`，`max steps` `6 -> 3`。
- 证据不足类题从 `7` 降到 `4`，说明“不要太早 unable to determine”的约束是有效的。
- 修回了 `7` 题，尤其是 [fish bag](iteration_02/task_04_5d0080cb.md)、[dragon word](iteration_02/task_13_b816bfce.md)、[Yankee at-bats](iteration_02/task_43_3f57289b.md) 这种原先明显靠错 source 或错计算失分的题。

### 坏消息

- 早答习惯没有改善，`invalid ANSWER` 甚至从 `99` 增到 `100`。
- “推理或事实判断错误”从 `14` 升到 `18`，成了更大的主矛盾。
- 两轮都对只有 `5` 题，两轮都错有 `36` 题。换句话说，这套 skill 目前还远没到“稳定收敛”的程度。
- 第二轮虽然修回 `7` 题，但也退化了 `5` 题，说明 actor 的改写方向还不稳。

## 当前还剩的系统层噪声

- [task_37_e142056d](iteration_01/task_37_e142056d.md) 在第一轮是手动 stop 后合成的中断态，它会把 iteration_01 的自动机失败统计抬高 `1` 题。
- 已污染的 `iteration_03` 没有纳入本页统计，不会混入结论。
- 除了这两个噪声点之外，本页统计已经能比较真实地反映前两轮 clean run 的问题结构。

## 建议

1. 如果目标是继续提分，优先级最高的不是继续堆 skill 文案，而是补附件工具链：音频转写、OCR/图像内容、PPTX/DOCX 抽取，以及更完整的表格语义。
2. 如果目标是把自动机真正压实，下一步应该把 “CONCLUDE 前置检查” 做成结构化状态，而不是继续依赖自然语言 prompt。
3. 对 `run_python` 的使用要从“建议”变成“半强制”。至少对 minimax、grid、string、small exhaustive search 这几类题，runtime 应当能检测并要求补一次程序化验证。
4. 统计层面建议把“流程已收敛但答错”和“流程未收敛”拆开单独看。当前这组 run 的主要矛盾已经明显偏向前者。
